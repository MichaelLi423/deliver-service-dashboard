# Vibe Coding 培训

本上下文记录 Vibe Coding 培训课程已明确的课程特定语言，供讲师与学员使用统一词汇讨论课程方法。业务术语以根目录 `CONTEXT.md` 为准，本词汇表不涉及。

## Language

**受控 AI 辅助开发**：
人定义目标、约束、决策与验收证据，AI 辅助进行分析与实现。本课程倡导此模式，不要把它称为无需监督的"纯 Vibe Coding"。
_避免使用_：纯 Vibe Coding、无人监督的 AI 开发

**开发闭环**：
从需求到交付的完整迭代循环：需求澄清 → 规范 → TDD 的 Red/Green 实现与验证 → 代码评审/规范核对。实现与验证有两个入口：TDD 面向已知目标行为（先写失败测试），diagnosis 面向未知故障原因（先收集证据）；任一步骤发现偏差即返回上一步修正，直到满足验收证据。
_避免使用_：跳过评审的一次性开发、流程外修补、把 TDD 与 diagnosis 混为一谈

**工具角色**：
先按职责理解工具（如编辑、生成、执行各自承担什么），具体产品只是实现该职责的示例。讨论以职责为准，不以产品名称代替。
_避免使用_：用产品名代替职责、工具操作清单

**混合演示**：
全部静态回放与少量现场操作组合而成的演示方式：连续编号的**静态重构材料**按步骤回放——这些材料依据已核验的会话步骤和历史输出摘要重新排版，是可编辑矢量重构，不是原始界面截图、不是录屏、不是现场 Agent 输出，保证内容确定、可复现、不依赖网络；现场只运行测试、查看 diff、切换快照、操作 UI。以回放为主、现场操作为辅，现场不调用 Agent。
_避免使用_：现场调用 Agent、全程现场操作、把重构材料说成原始界面截图或录屏

**演示需求**：
培训演示选用的需求，须来自当前项目、范围小、存在真实歧义、可通过观察验证，并使用脱敏数据。这些条件保证演示贴近真实且可复现。
_避免使用_：虚构需求、无法观察的验收、含敏感数据的示例

**Vibe Coding**：
本课程对外名称，在本上下文中指受控 AI 辅助开发，不代表无人监督生成。不要把它当作"凭感觉接受输出"的做法。
_避免使用_：凭感觉接受输出、无人监督生成

**风险适配**：
流程强度按业务歧义、改动范围、公共 API、数据/安全影响调整。但目标、边界、验证证据在任何强度下都不可省略。
_避免使用_：一律全流程、完全随意

**质量双门**：
代码评审与规范核对两个互补的检查关口：代码评审关注安全、清晰与可维护，规范核对关注约定行为与证据。二者互补，不可互相替代。
_避免使用_：单一口径检查、评审与核对二选一

**预设失败**：
混合演示中刻意准备的、表面可运行但违反领域规则或规范的输出，用于展示证据如何纠偏。这是教学安排，不是真实故障。
_避免使用_：真实故障、意外报错

**培训夹具**：
为课程准备的可运行代码、测试与阶段快照，可包含预设失败。它们不等于获批的产品需求或待合入的产品变更；正确实现只有经另行确认后才能进入正式产品变更。
_避免使用_：正式需求、可合入的产物

**待答问题池**：
现场无法在共性 Q&A 时间解决的个人配置或扩展问题，集中记录并约定会后书面处理。它是课堂纪律安排，不用作规范术语。
_避免使用_：parking lot

**安全红线**：
课程不展开治理体系，但演示必须遵守的最低约束：不上传敏感信息、不展示密钥、AI 无生产权限、破坏性/数据/依赖/合并发布操作需人工确认。
_避免使用_：完整治理流程、自动放行高风险操作

**公开培训资产**：
可进入当前公开仓库的脱敏课程材料和项目演示夹具。不含公司政策、账号、真实问答或组织信息。
_避免使用_：内部课件、含公司信息的材料

**内部附件**：
仅存放于私有空间的公司特定政策、账号说明和真实 Q&A。本次只在公开材料标注注入点，不创建真实附件。
_避免使用_：公开仓库中的公司政策、真实问答

**四阶段快照**：
演示分支上 baseline、red-test、preset-failure、green-final 四个有序 Git 状态，用于在无现场 Agent 时稳定回放 Red/Green 与纠偏。它们属于培训夹具，不是产品交付。
_避免使用_：产品发布版本、真实交付历史
