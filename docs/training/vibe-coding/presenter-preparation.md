# 讲师备课手册（presenter-preparation）

本手册用于讲师备课、彩排和现场控场，不替代逐分钟口播稿（[speaker-notes.md](./speaker-notes.md)）。课程总时长 90 分钟、34 页、技术混合受众、全部静态回放。演示机械细节见 [demo-runbook.md](./demo-runbook.md)，术语以 [CONTEXT.md](./CONTEXT.md) 为准，业务词汇以仓库根目录 [CONTEXT.md](../../../CONTEXT.md) 为准。

## 1. 课程边界

### 目标

1. 学员能判断：一个任务该交给 AI 多少，人必须守住目标、约束、决策、验收证据这四样。
2. 学员会开一次受控编码会话：看懂仓库状态、会话状态、模式切换（Build 默认、显式切 Plan）、allow/ask/deny 权限、diff、undo、验证。
3. 学员能区分三套工具的定位（skills 技能包、oh-my-opencode-slim 编排、OpenSpec 规范验收），并说清 MCP 的适用边界。
4. 学员能区分 TDD 与 diagnosis 两个入口，复述四层证据（strict 结构、规范映射/启发式核对、机器执行证据、code review 质量）。

### 受众与形式

- 线下 10–30 人，90 分钟，34 页；技术混合受众（开发为主，含产品/测试/运维）。
- 不跟做、无考核、无退出卡；所有 Agent 输出为静态回放，现场不调用 Agent。
- 学员不需要安装任何工具；工具安装命令只做讲解，不在课堂执行。

### 明确不讲什么

- 不现场调用 Agent、不做学员跟做、不讲完整模型/提示词工程。
- 不讲公司政策、账号、真实 Q&A、组织信息或敏感数据。
- 不讲个人 IDE 配置；MCP 只讲边界，不演示连接外部系统。
- 不把 oh-my-opencode-slim 说成官方、不把 mattpocock/skills 说成官方标准、不把 MCP 说成单一运行时。
- 不把 OpenSpec strict 当行为验证；不把 macOS arm64 结果说成 Windows 验证；不把培训夹具说成产品批准。
- 必须讲归档漂移：原 change 已归档、正式 spec 是旧版、最终实现只在远端培训分支、training-change 只是教学夹具。

## 3. 34 页逐页讲解卡

> 每页只服务一个观点。时长 = 口播 + 回放/操作。页 8–11 与页 29–32 的"回放"指**连续编号的静态重构材料**——依据已核验的会话步骤和历史输出摘要重新排版，不是原始界面截图、不是现场 Agent 输出，PPT 不嵌入原始图片。

### 页 1 封面

- **时长**：1 分钟
- **唯一观点**：本课讲"从需求到证据的受控开发闭环"。
- **页面内容**：标题《Vibe Coding》+ 副标题；90 分钟、34 页、静态回放、不跟做无考核四行说明。
- **建议口播**：报时安排：概念 8、会话 12、工具 22、方法 12、演示 22、落地 6、问答 8。
- **转场句**："先告诉你学完能做什么。"
- **不要展开**：工具安装、个人配置、公司背景。
- **对应资料**：[README.md](./README.md)

### 页 2 学完能做什么

- **时长**：1.5 分钟
- **唯一观点**：三个可检验的收获，对应后面七个章节。
- **页面内容**：三行收获 + 一行"现场不调用 Agent，全部静态回放"。
- **建议口播**：判断 AI 该做多少；开受控会话；用四层证据确认做对了。
- **转场句**："先统一四个基本概念。"
- **不要展开**：证书、考核、工具采购。
- **对应资料**：[workflow-checklist.md](./workflow-checklist.md)

### 页 3 模型 / Agent / tool / session

- **时长**：2 分钟
- **唯一观点**：会话是操作单元，四个概念各有边界。
- **页面内容**：四概念一列图示；session 下方标"工作目录、上下文、权限"。
- **建议口播**：模型是引擎，Agent 是执行主体，工具是能力，session 是容器。
- **转场句**："会话里谁说了算？"
- **不要展开**：模型架构、推理原理、提示词技巧。
- **对应资料**：[CONTEXT.md](./CONTEXT.md)

### 页 4 受控开发

- **时长**：2 分钟
- **唯一观点**：人定义目标、约束、决策、验收证据，AI 辅助分析与实现。
- **页面内容**：四要素四象限图；一行"凭感觉接受输出"打叉。
- **建议口播**：Vibe Coding 在本课就是受控 AI 辅助开发。
- **转场句**："先说一条任何工具都越不过的红线。"
- **不要展开**：Vibe Coding 起源争论、行业八卦。
- **对应资料**：[CONTEXT.md](./CONTEXT.md)

### 页 5 安全红线

- **时长**：1.5 分钟
- **唯一观点**：不上传敏感信息、不展示密钥、AI 无生产权限、高风险操作人工确认。
- **页面内容**：四条红线，逐条大字。
- **建议口播**：60 秒读完；"这不是治理体系课程，但这是最低约束。"

### 页 10 首次会话·步骤 3：模式与权限

- **时长**：2 分钟（口播 1.5 + 回放 0.5）
- **唯一观点**：默认主 Agent 是 Build；回放显式切到 Plan，只有命中 ask 的操作才请求批准。
- **页面内容**：静态重构材料③——Plan 模式切换与 permission 配置（编辑/bash 为 ask）、命中 ask 的批准请求；一行说明"权限三值 allow/ask/deny，默认多数权限为 allow"。
- **建议口播**：显式切到 Plan；权限三值 allow/ask/deny——默认多数操作 allow 直接放行，命中 ask 才弹批准，deny 直接拒绝。权限是人握方向盘的具象化。
- **转场句**："改完了，怎么看改没改对？"
- **不要展开**：权限配置全枚举、企业策略。
- **对应资料**：[demo-runbook.md](./demo-runbook.md)

### 页 11 首次会话·步骤 4：diff / undo / 验证

- **时长**：2 分钟（口播 1.5 + 回放 0.5）
- **唯一观点**：diff 把关、undo 单步回退、验证给证据。
- **页面内容**：静态重构材料④——diff 视图、`/undo` 结果、测试输出三份排版；一行说明"`/undo` 单次撤销上一条用户消息及其后的回复与文件改动；可连续执行 `/undo` 继续向前，`/redo` 恢复；跨会话或需要明确版本点时依赖 Git"。
- **建议口播**：先看 diff 有没有夹带；错了 `/undo` 单步回退，可连续 `/undo` 继续向前、`/redo` 恢复，跨会话或版本点用 Git；最后跑验证。
- **转场句**："会话本身会了，再选工具。"
- **不要展开**：Git 内部原理、任意检查点回退。
- **对应资料**：[demo-runbook.md](./demo-runbook.md)

## 7. 讲师容易犯的错误

- 把 OpenSpec strict 的"Change is valid"说成行为已验证——strict 只验结构；且原 change 已归档，当前 HEAD 不能重跑该命令，只能展示 2026-08-10 历史输出。
- 把 macOS arm64 证据说成 Windows 验证——所有历史证据来自 macOS 开发机。
- 把 oh-my-opencode-slim 说成 OpenCode 官方、把 mattpocock/skills 说成官方标准——前者是社区插件，后者是个人技能包。
- 把 MCP 说成必装单一运行时——它是协议，本项目无配置，本课不演示。
- 把 training-change 夹具说成产品 change 或产品批准——正式合入需另立正式 change 并走评审。
- 把"无额外业务上限"说成任意大整数——只接受 0..9007199254740991 的非负安全整数。
- 现场调用 Agent、展示密钥、把 `WORKBENCH_E2E_USER_DATA_DIR` 指向日常数据目录。
