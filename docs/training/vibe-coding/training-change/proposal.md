# 培训提案（夹具）：提醒临期窗口配置入口

> **培训夹具，非产品提案。** 本文件用于备课和历史会话不可访问时说明"当时提案长什么样"，不构成产品决策，也从未走产品批准流程。来源：培训分支 `origin/training/vibe-coding-reminder-window` 的叙事（origin 于 baseline `76747c1`）。

## Why

搬迁负责人需要在工作台"项目提醒快速处理"面板中直接调整临期窗口（默认 7 个自然日），按项目节奏决定多远的提醒算"临期"。课程用这个需求演示：需求澄清（grill）如何暴露边界歧义，规范如何把这些歧义写死为可验收场景。

## 澄清结论（grill 收敛）

- **0 是否合法？** 合法：窗口为 0 时未来提醒不归入临期分类，今日到期与已逾期分类不受影响。
- **数值边界？** 仅接受 0 到 `9007199254740991`（含）之间的非负安全整数；无额外业务上限；负数、非整数、超出安全整数精确可表示范围的值拒绝且不生效。
- **保存时机？** 编辑中的值在显式保存前不生效；保存后立即按新窗口刷新当前工作台；配置持久化、关闭重开保持。
- **日期可见？** 工作台提醒行展示提醒日期与对应到期分类。

## What Changes

- 在工作台提醒面板提供"临期窗口"数字输入与显式保存按钮。
- 保存后立即按新窗口在当前工作台重新分类；配置经 `app_settings` 持久化。
- 提醒行展示格式化提醒日期与到期分类。

## Scope

- 临期窗口配置入口 + 边界校验（非负安全整数）+ 持久化 + 保存后立即刷新 + 提醒日期可见。

## Non-Goals

- **无独立 reset 功能**：本夹具不包含"恢复默认窗口"按钮；这是夹具范围约定，不是产品决策，也不是正式规格的一部分（见 [spec.md](./spec.md) 与 [evidence.md](./evidence.md)）。
- 不改变提醒手工维护模型、不新增提醒完成历史、不接入任何外部消息渠道。
- 不冒充正式产品决策：本提案的最终实现只在远端培训分支，当前 main 不合入；如需产品化须另立正式 OpenSpec change。

## Impact

- 影响面：workbench-todos 能力（spec）、IPC mutation（`set_window_days`）、工作台 UI、`app_settings` 持久化。
- 风险：低；仅影响工作台内展示与到期分类，无外部副作用。
- 培训价值：一条需求走完"澄清 → 规范 → Red → 预设失败 → Green → 评审/核对"闭环。
