# 历史数据导入执行与运维说明

> 本文件是 10.6 交付文档：面向部署运维人员与搬迁负责人的运行、部署、数据目录、
> 无访问门槛与数据保护边界、备份/恢复、**历史数据导入向导**操作说明（模板/文件/Excel 粘贴/
> 七类声明/草稿/错误冲突/完整校验与封存/备份/原子提交/中断恢复/审计）、
> ECC 聚合导入键、重复服务单号冲突处理、Excel/PNG/PDF 导出说明。
> 不含 UI 视觉设计约定。历史数据导入的唯一入口是工作台内向导，不提供外部命令行入口。

## 0. 保护边界（重要声明）

- **无应用内访问门槛、SQLite 不加密**：应用为个人单机使用，启动直接进入工作台，没有应用内初始化、密码登录、恢复码、多账号或角色；内部唯一"本地用户"仅用于事实归属与用户名快照，不是访问门槛。数据库文件是普通 SQLite 文件，内部本地用户**不能**防止直接读取数据库文件。
- **数据文件与备份的主要保护边界为 Windows 操作系统账户**：应通过 Windows 操作系统账户、文件系统 ACL 与磁盘加密（如 BitLocker）保护 `userData` 目录与备份目录。

## 1. 部署与运行

### 1.1 Windows（交付目标）

- 构建安装包：`npm run make`（Electron Forge + MakerSquirrel 产出 Windows 安装包）。
- 安装：运行生成的 Squirrel 安装包完成安装；应用为个人使用的 Windows 桌面程序。
- 运行：从开始菜单启动「搬迁服务工作台」，启动后**直接进入工作台**（无应用内初始化或登录）。
- Windows 目标环境验收已由客户确认（tasks 8.85）。

### 1.2 macOS 开发机（验收环境）

- 打包应用：`npm run e2e:build`（产出 `out/搬迁服务工作台-darwin-arm64/搬迁服务工作台.app`）。
- 运行 E2E：`npm run test:e2e`（Playwright + 真实 Electron 打包产物，临时 userData 运行）。
  macOS 上的通过仅验证开发机可运行性，**不冒充 Windows 验证**；
  Windows 安装包与 Windows 操作系统账户保护已由客户在 Windows 目标环境验收（8.85）。

### 1.3 开发运行

- `npm start`（electron-forge start，开发模式）。
- 常用校验：`npm run typecheck`、`npm test`（Vitest 领域/集成/持久化测试）、
  `npm run verify:matrix`（场景→测试矩阵一致性校验）。

## 2. 无访问门槛与数据保护边界

### 2.1 启动与使用

- 应用启动后**直接进入工作台**，不提供应用内初始化、密码登录、恢复码、账号切换或多账号/角色。
- 内部唯一"本地用户"仅用于记录手工录入事实与工作量的归属（持久化用户内部 ID 与当时用户名快照），
  历史统计不因用户名修改而动态变化。

### 2.2 数据保护边界

- SQLite 数据库**不加密**；数据文件与备份的主要保护边界为 **Windows 操作系统账户**
  （配合文件系统 ACL 与磁盘加密，如 BitLocker）。
- 内部本地用户不是访问门槛，不能防止直接读取数据库文件。

## 3. 数据目录

| 路径（位于 Electron `userData` 下） | 内容 |
| --- | --- |
| `data/workbench.db` | 本机 SQLite 数据库（全部业务数据，不加密） |
| `data/` | 数据目录（bootstrap 初始化） |
| `import-workspace/` | 历史数据导入工作区数据库（草稿/修订/规范化行/来源/问题/校验封存） |
| `import-snapshots/` | 导入提交前安全快照（原子提交失败保护） |
| `backups/auto/` | 每日自动备份（`auto-YYYY-MM-DD.db`，仅保留最近 7 份） |
| `backups/manual/` | 手动备份输出目录（用户自选目标目录） |
| `restore-snapshots/` | 恢复前安全快照（原子恢复失败保护） |

- 数据库连接使用 WAL / foreign_keys / busy timeout；数据结构升级通过 `PRAGMA user_version`
  迁移，迁移失败保留可恢复状态。
- 导入工作区与正式业务库物理隔离：损坏/版本不兼容时仅禁用导入，不影响普通工作台。
- **Windows 打包后** `userData` 实际路径由 Electron 按 Windows 应用数据目录解析；
  应确认所在磁盘已启用操作系统账户保护。

## 4. 备份与恢复

### 4.1 每日自动备份

- 每日首次使用且当天尚无自动备份时自动创建；自动备份**仅保留最近 7 份**，更旧的自动
  备份被清理；手动备份不受数量限制。

### 4.2 手动备份

- 在应用内选择「手动备份」并指定本地目录，立即生成完整备份文件（在线 backup）。

### 4.3 恢复

- 从所选备份恢复前需确认；恢复前创建安全快照，恢复过程为原子替换。
- 恢复前校验备份可读（integrity_check）；备份损坏/不可读时**停止恢复、不覆盖当前数据**，
  并给出明确错误（不静默成功）。
- 恢复后建议立即核对业务数据，随后进行一次手动备份。

## 5. 历史数据导入（工作台向导，唯一入口）

历史数据导入**只能**通过工作台「数据管理 → 历史数据导入」向导执行；
向导全部操作经 `import-wizard:*` 通道、受信窗口会话与 trusted sender 守卫校验，**不存在外部命令行入口**。
自由文本 operator 与命令行已被移除；导入的归属记录来自内部唯一本地用户。

### 5.1 操作流程

1. **进入**：在受信工作台窗口打开工作台（无应用内登录，见 2.1），在「数据管理」中选择「历史数据导入」；非受信窗口不能进入向导。
2. **进入**：在「数据管理」中选择「历史数据导入」，新建或继续草稿。
3. **模板**：可下载当前版本空白模板（填写说明 + 七类业务 sheet），按说明填写
   `source_row_id` 与目标字段（标识符按文本保留前导零、金额两位小数、业务日期
   yyyy-mm-dd——历史值按升级时本机业务时区转换为业务日期；不接受时分秒与
   公式/宏/DDE/外链）。
4. **文件**：选择一个或多个 Excel 文件；读取与规范化在独立工作线程执行，可取消，
   取消后回到最后稳定修订（不形成部分合并）。
5. **Excel 粘贴**：支持从 Excel 矩形区域复制后粘贴，确认首行为表头或业务数据；
   大粘贴按块写入，可取消并回到保存边界。
6. **七类声明**：项目与合同、开单记录、掉票记录、物流费用、序列号地址更新、
   二维码申请、Ship-to 申请逐类显式声明「有数据 / 本次无数据」；未声明类别阻止提交。
7. **草稿与修订**：所有修改按乐观修订号保存；运行期重启恢复到最后稳定修订。
8. **错误与冲突**：完整校验把错误/冲突/警告定位到网格单元格，逐项修正或选择来源
   候选；阻断项不解决不能提交。
9. **完整校验与封存**：校验通过后生成 validation seal（绑定计划摘要、规则版本、
   目标库身份与业务修订）；任何草稿修改、规则/schema 升级、目标数据变化都会使封存失效。
10. **备份与原子提交**：提交前事务外创建并验证安全快照（快照失败零业务写入）；
    单个立即写事务内复核封存并一次写入七类 + 来源审计 + 目标快照 + 运行审计 + 对账。
11. **中断恢复**：提交中断后按「成功审计 + 完整事务」判定完整成功，否则完整回滚并
    要求重新完整校验；解析/校验中断由重启恢复回滚到最后稳定修订。
12. **审计**：运行审计（import_run）记录内部本地用户 ID 与提交时用户名快照、
    operation id、计划摘要、规则版本、七类计划与写入数、pre/post 业务修订；
    导入的业务事实标记为历史导入来源，**不计入本地用户的手工工作量**。

### 5.2 源数据要求与边界

- 有界预检限制资源攻击：单文件/批次数、ZIP 展开量、sheet/行列/单元格上限；
  宏、DDE、外部链接与不可安全读取的公式拒绝或置空，不执行不联网。
- 历史事实以 ECC 为项目/合同聚合主键导入并作为一个搬迁项目展示；导入时间只进审计，
  不替代源业务日期；源业务日期进入对应业务字段并按升级时本机业务时区转换为业务日期
  （yyyy-mm-dd）。所有业务时间仅记录业务日期，审计/技术时间保留精确 ISO
  （见 `docs/搬迁服务工作台.md` §6.7 与 openspec design D30）。

## 6. ECC 聚合与导入键

- 以 **ECC 为项目/合同聚合主键**：同一 ECC 下一个合同的全部执行数据聚合为一个搬迁项目。
- 服务单号、Account ID、序列号仅用于子记录识别与冲突处理，不与 ECC 同级匹配项目。
- 无业务键的记录以「来源 + 行号」为记录键，用于幂等与冲突处理；重排行可能改变身份，
  最终确认前向导会提示风险。
- 缺 ECC 的项目/合同执行数据在完整校验阶段报必填错误且该记录不可提交。

## 7. 重复服务单号冲突

- 不同源记录存在**重复的非空服务单号**时进入冲突清单；**解决前该批次整批禁止提交**。
- 冲突项只定位来源、物理行与目标字段，**不含具体单号值**，由负责人逐项确认。
- 冲突消除（如修正服务单号）后重新执行完整校验再提交。

## 8. 报表三种导出

- 运营报表支持导出 **Excel（.xlsx）**、**图片（PNG）** 与 **PDF** 三种格式。
- 导出内容为**当前筛选条件下的实时结果**，与报表页实时计算结果一致；导出成功给出反馈，
  失败（含取消保存对话框）就地提示、不静默成功。
- 导出不包含 CSV（规格明确仅三种格式）。

## 9. 故障与恢复要点

- 数据库损坏：停止使用，使用最近一次可用备份恢复（见 4.3）。
- 导入提交失败：整体回滚，不产生部分数据；草稿保留并要求重新完整校验后再提交。
- 导入中断（应用在解析/校验/提交期间退出）：重启后恢复确定性结果——
  解析/校验回到最后稳定修订；提交按成功审计判定完整成功或完整回滚。
- 数据保护：SQLite 不加密，数据文件与备份的主要保护边界为 Windows 操作系统账户（见 0 与 2）。

  operator 均已移除，打包产物不包含任何隐藏 CLI 入口。
