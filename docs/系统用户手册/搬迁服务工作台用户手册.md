# 搬迁服务工作台 · 用户手册

> 本手册面向**日常使用工作台的人**（搬迁负责人）。按实际界面按钮、菜单和步骤编写，
> 只描述当前版本中真实可用的功能。
>
> - 版本对应：应用 0.1.0（私有，未发布）。本手册描述的界面以当前代码为准。
> - 术语以《CONTEXT.md 领域语言》为准（掉票≠发票/回款；搬迁项目≠合同）。
> - 部署、数据目录、备份恢复细节与历史数据导入的运维口径，见
>   [`迁移执行与运维说明`](../verification/迁移执行与运维说明.md)。
>
> **时间口径**：所有业务日期字段（进单日期、开单日期、实际装机完成日期、掉票日期、
> 提醒日期、更新日期、申请日期等）在界面均使用**日期控件**（yyyy-mm-dd）录入与筛选；
> 业务记录只保存业务日期，不带时分秒与时区。系统内部单独保存的审计/技术时间
> （如最后修改时间）不显示为业务录入字段。

## 1. 首次使用检查清单

第一次拿到工作台时，按下面的顺序做一遍（每项对应的详细步骤见相应章节）：

| # | 事项 | 说明 | 详见 |
| --- | --- | --- | --- |
| 1 | 安装并启动 | 运行安装包，从开始菜单启动「搬迁服务工作台」 | [2.1](#21-首次启动初始化) |
| 2 | 创建本地账号 | 唯一的用户名 + 密码（建议至少 8 位） | [2.1](#21-首次启动初始化) |
| 3 | **离线保存恢复码** | 恢复码只展示一次，是忘记密码时唯一恢复凭据 | [2.2](#22-一次性恢复码只展示一次) |
| 4 | 确认数据在本机 | 业务数据只保存在本机，不联网、不上云 | [19](#19-数据与安全边界) |
| 5 | 建立备份习惯 | 每日自动备份；重要节点做一次手动备份 | [16](#16-备份与恢复) |
| 6 | 从新建项目开始 | 顶部「新建搬迁项目」，四步向导创建第一个项目 | [5](#5-新建搬迁项目四步向导与三种保存方式) |

> **务必**：恢复码不要和数据库备份放在同一个位置（例如不要放在同一个文件夹、同一块没有加密的 U 盘）。
> 恢复码相当于账号的最后恢复凭据。

## 2. 首次账号、恢复码与登录

工作台只有一个本地账号作为**访问门槛**（不是安全加密）。首次启动必须创建，之后每次启动需要登录。

### 2.1 首次启动初始化

1. 启动应用，进入「首次使用初始化」页面。
2. 填写**用户名**和**密码**（密码建议至少 8 位，便于离线管理）。
3. 点击 **创建账号并继续**。
4. 创建成功后**只展示一次**一次性恢复码，进入「离线保存恢复码」页面。

### 2.2 一次性恢复码（只展示一次）

- 页面显示一段**恢复码**（一次性），并提示「此恢复码不会再次显示」。
- 点击 **复制恢复码** 复制到剪贴板，然后粘贴到离线密码管理器或纸质记录保存。
- 点击 **我已离线保存** 进入工作台。
- 恢复码**使用后立即失效**，并在下次重置时生成新的恢复码。

### 2.3 后续登录

1. 再次启动显示「登录本地工作台」。
2. 输入用户名与密码，点击 **登录工作台**。
3. 登录建立的是应用内会话：关闭应用重开后需要重新登录。

> 登录页可能显示一条黄条警告「自动备份失败：…」。这说明今天的自动备份没做成功，工作台仍可正常使用，
> 但请尽快**手动备份**（见 [16.2](#162-手动备份)）。

### 2.4 忘记密码：使用恢复码重置

1. 在登录界面点击 **忘记密码？使用恢复码**。
2. 输入离线保存的**恢复码**和**新密码**。
3. 点击 **重置密码**。
4. 重置后进入新恢复码展示页：**原恢复码立即失效**，请保存新的恢复码，再点击 **我已离线保存**。
5. 之后用新密码登录。

> 恢复码用掉一次就不能再用了。如果又忘记密码，需要凭最新保存的那份恢复码再次重置。

## 3. 工作台布局

登录后进入主工作台，从上到下、从左到右的板块如下。

### 3.1 顶部导航栏

| 按钮 / 菜单 | 作用 |
| --- | --- |
| 搬迁服务工作台（品牌区） | 点击回到主区域开头 |
| **项目提醒** | 跳到「项目提醒快速处理」面板 |
| **项目队列** | 跳到「高密项目队列」 |
| **序列号地址更新** | 打开独立模块抽屉（逐台记录序列号实际关联地址） |
| **二维码申请** | 打开独立模块抽屉（申请仪器服务 / 项目验收单 / 物流管理二维码） |
| **运营报表** | 打开报表抽屉（手工月份区间 + 导出） |
| **数据管理**（下拉） | ▸ **历史数据导入** · ▸ **手动备份** · ▸ **恢复备份** |
| 右上角账号圆点 + 用户名 | 显示当前登录账号 |

### 3.2 任务指挥台

- 标题「先处理提醒，再连续推进项目」，并有说明：提醒由负责人手工维护；空字段不会自动生成提醒。
- 右侧两个按钮：
  - **快速记录**：为当前选中项目就近录入业务动作（需先在项目队列选中一行，详见 [7](#7-九类快速记录)）。
  - **新建搬迁项目**：打开四步新建向导（详见 [5](#5-新建搬迁项目四步向导与三种保存方式)）。

### 3.3 关键运营指标

四个指标卡：

| 指标 | 含义 |
| --- | --- |
| 活跃搬迁项目 | 当前非终态项目数（副标题给出项目总数） |
| 当前项目提醒 | 有提醒的项目数（副标题给出逾期 / 今日数） |
| 待掉票金额 | 按最终可确认金额口径计算 |
| 待验收 / 待掉票 | 当前生命周期瓶颈（副标题提示） |

### 3.4 生命周期吞吐

- 六个阶段按钮（待进单、待执行、执行中、待验收、待掉票、已完成），显示各阶段**项目数**与**平均停留天数**。
- 点击某个阶段按钮 = 用该状态筛选项目队列（按钮会高亮）。
- **全部项目**：清除状态筛选，回到全部项目。
- 底部可能显示「当前瓶颈：×」提示，建议优先核对瓶颈阶段的项目。

### 3.5 项目提醒快速处理

- 标题「项目提醒快速处理（数量）」，按最接近当天的提醒日期排序。
- 每条提醒显示：到期分类（**已逾期 / 今日 / 临期 / 备注**）、客户名称、ECC（或临时编号）、提醒备注。
- 点击某条提醒 = 直接跳到对应项目，并按「提醒=有提醒 + 查找该客户/编号」筛出项目队列。
- **查看全部**：按「有提醒」筛选项目队列。

### 3.6 高密项目队列

- 标题「高密项目队列（总数）」，服务端 keyset 分页，每页最多 50 项。
- 表格列：客户 / ECC（未进单、未进单先执行有文字角标）、主状态、区域、提醒、批次 / 仪器、累计掉票、更新日期、就近录入。
- 每一行「就近录入」列有 **记录** 按钮，点击直接为该行项目打开快速记录。
- 点击（或键盘选择）任意一行，右侧「当前上下文」和下方「项目详情」随之切换。
- 空结果时显示「没有符合条件的项目」。

### 3.7 当前上下文（常驻侧栏）

随选中的项目联动，包含：

- **状态与辨识**：主状态徽章、已进单 / 未进单、未进单先执行、Ship-to 待处理、二维码待标记、损坏/维修等提示。
  - **人工调整主状态**：下拉框选择状态 → **提交校验**（规则见 [6](#6-七个主状态自动与人工规则)）。
  - **取消项目**：红色按钮，见 [9](#9-取消项目)。
- **当前项目提醒**：提醒日期与备注。
- **金额闭环**：最终可确认、累计掉票、待掉票。
- **执行联系**：旧址联系人 · 新址联系人。

### 3.8 项目详情（六个选项卡）

- 顶部显示：合同 USD 含税金额、最终可确认金额、累计掉票。
- 选项卡：**项目总览 / 搬迁仪器 / 搬迁批次 / 上门活动 / 费用与掉票 / 申请与维修**。
- 每个业务选项卡右侧有 **就近记录** 按钮，直接打开与该选项卡对应的录入表单。
- 「项目总览」显示：主状态、进单日期（未进单显示"待进单"）、所属区域、合同开始 / 截止日期、搬迁批次、搬迁仪器、上门活动数量。

各选项卡的列表字段：

| 选项卡 | 列 |
| --- | --- |
| 搬迁仪器 | 仪器名称、型号、序列号、搬迁批次、UPS、二维码是否申请 |
| 搬迁批次 | 计划运输日期、运输公司、费用登记日期、合同预算价、物流成交价、运输开始日期 |
| 上门活动 | 到访日期、参与工程师 |
| 费用与掉票 | 掉票日期、金额、状态、撤销日期，操作列（编辑 / 撤销，终态显示「终态 · 更正请新增」） |
| 申请与维修 | 仪器名称、序列号、损坏原因、事项状态、备件号、备件金额、备件状态 |

## 4. 筛选、分页与键盘操作

### 4.1 项目队列筛选

「高密项目队列」上方筛选区（改完点 **筛选** 生效，**清除** 重置为全部）：

- **主状态**：全部状态 / 待进单 / 待执行 / 执行中 / 待验收 / 待掉票 / 已完成 / 已取消

## 5. 新建搬迁项目：四步向导与三种保存方式

顶部点击 **新建搬迁项目**，打开四步向导（步骤指示：基本信息 → 搬迁范围 → 执行准备 → 确认方式）。

**第 1 步 · 基本信息**

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| 客户名称 | 必填 | 去除首尾空白后全局唯一 |
| 区域 | 必填 | 手工填写文本 |
| 合同 USD 含税金额 | 可后补 | **仅此项允许为 0**；正式进单且金额为 0 时必须补最终可确认金额 |
| 合同开始日期 | 必填 | |
| 合同截止日期 | 必填 | |

**第 2 步 · 搬迁范围**

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| 旧址地址 | 必填 | 项目默认旧址 |
| 新址地址 | 必填 | 项目默认新址 |
| 仪器名称 | 必填 | |
| 型号 | 可后补 | |
| UPS | 选择 | 否 / 是 |

**第 3 步 · 执行准备**

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| 计划上门日期 | 可后补 | 不触发状态流转 |
| 计划运输日期 | 可后补 | 不触发状态流转 |
| 实际装机完成日期 | 可后补 | 一旦录入会**自动进入待验收**（见 [6](#6-七个主状态自动与人工规则)） |
| 现场条件已确认 | 勾选 | 不触发状态流转 |

**第 4 步 · 确认方式**

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| ECC | 可后补 | 正式进单前必须补齐 |
| 进单日期 | 可后补 | 正式进单时未填则取当天，允许补录 |
| 最终可确认金额（USD） | 可后补 | |
| 经理批复原因 | 可后补 | 未进单先执行时需要 |
| 缺失资料 | 可后补 | 未进单先执行时需要 |

**三种保存方式**（第 4 步底部三个按钮）：

| 按钮 | 含义 | 效果 |
| --- | --- | --- |
| **保存为待进单** | 只登记，暂不正式进单 | 项目主状态为「待进单」，合同可空 |
| **未进单先执行** | 经经理批复后先安排上门 | 主状态保持「待进单」并打上「未进单先执行」标签；正式进单前不能离开待进单 |
| **正式进单** | 补齐 ECC、进单日期等并确认接手 | 按业务条件完整校验；校验通过后成为「已进单」项目 |

向导内「上一步 / 下一步」随时可切换，字段只在提交时校验。

> 已进单与未进单项目在界面上颜色标识明显不同；「未进单先执行」项目正式进单后标签清除，主状态由负责人重新确定。

## 6. 七个主状态：自动与人工规则

项目主状态共七个：

> **待进单 → 待执行 → 执行中 → 待验收 → 待掉票 → 已完成**；终止项目为 **已取消**。

### 6.1 自动触发（优先于人工选择）

| 触发条件 | 结果 |
| --- | --- |
| 录入**实际装机完成日期** | 自动变为 **待验收** |
| 记录**验收报告**并填写报告形成日期 | 自动变为 **待掉票**（不要求先到待验收；取消项目除外） |
| **掉票金额闭环** | 在待掉票 / 已完成之间自动重算：累计有效掉票 ≥ 最终可确认金额 → **已完成**；否则保持 **待掉票** |

### 6.2 人工调整

在「当前上下文」中选择目标状态并点击 **提交校验**。保存时会校验：

- 目标状态必须是七个合法状态之一。
- **已取消是终态**：不可恢复，继续工作需重新新增项目。
- **取消约束**：存在任何掉票历史（**含已撤销**）的项目禁止取消。
- **金额闭环约束**：不能直接调成「已完成」——必须先录入**大于 0** 的最终可确认金额，且累计掉票达到该金额。
- 调到「执行中」需要执行确已开始（首次上门活动开始，或首个搬迁批次开始运输；仅完成排期 / 安排运输公司不算）。
- 带「未进单先执行」标签的待进单项目，主状态保持待进单；正式进单后由负责人重新确定。

> 校验不通过时，界面就地显示原因，状态不会被改掉。

### 6.3 未进单先执行

- 经理批复（批复原因、缺失资料）由负责人**手工记录**（新建向导第 4 步或快捷动作「补齐进单核心资料」附近字段）。
- 标签存在时主状态锁定在「待进单」；正式进单后按已发生事实和人工选择重新校验。

## 7. 九类快速记录

在项目队列选中一行后：

- 顶部 **快速记录**，或
- 当前上下文 **快速记录**，或
- 队列行「就近录入」列的 **记录**，或
- 项目详情业务选项卡的 **就近记录**。

打开「快速记录」菜单，共九类动作（都写入**当前选中项目**）：

## 8. 掉票：新增、编辑、撤销与更正

掉票 = 项目验收后，负责人按 ECC 向财务提交可确认金额的业务动作。掉票记录**发生日期 + 金额**，不代表客户开票、回款或现场执行完成。

### 8.1 新增掉票

「费用与掉票」选项卡 → **就近记录**（或快速记录 → 掉票），填写掉票日期与掉票金额（USD），保存。

> 新增加一条掉票后，累计掉票不得超过最终可确认金额；相关校验不通过时保存会失败并就地提示。

### 8.2 编辑有效掉票

- 「费用与掉票」列表里，**有效**（未撤销）掉票行有 **编辑** 按钮。
- 点击进入「编辑掉票」：可修改**掉票日期**与**掉票金额**，点 **保存修改**。
- 只有有效掉票能直接编辑。

### 8.3 撤销掉票

- 有效掉票行有 **撤销** 按钮。
- 点击进入「撤销掉票」：填写**撤销日期**、**撤销原因**，勾选「我确认撤销后不可恢复」，点 **确认撤销掉票**。
- **撤销后为终态**：不能编辑、不能重复撤销、不能重新激活。列表行显示「终态 · 更正请新增」。

### 8.4 更正掉票

撤销后如需更正，**新增一条有效掉票**（不要尝试改旧记录）。

> 存在任何掉票历史（含已撤销）的项目**禁止取消**（见 [9](#9-取消项目)）。

## 9. 取消项目

「当前上下文」→ **取消项目**（未取消的项目才有此按钮）。

1. 弹出「取消项目」表单，提示：取消为终态不可恢复；存在任何掉票历史（含已撤销）的项目禁止取消。
2. 填写**取消日期**（默认当天）与**取消原因**（必填）。
3. 勾选「我确认项目取消后不可恢复」。
4. 点击 **确认取消项目**。

规则：

- 取消为**终态**，继续工作需重新新增项目。
- 取消会保留已发生的上门活动、物流与费用记录。
- 取消期间禁止修改合同金额、最终可确认金额与掉票记录。
- 已取消项目被排除在收入 / 掉票相关统计之外。

## 10. 项目提醒

### 10.1 维护提醒

- 「当前上下文」→ **维护提醒**（或快速入口）。

### 10.2 到期分类与快速处理

- 临期窗口默认为**未来 7 个自然日**（当前界面不提供修改入口，见 [20](#20-当前界面限制与未验证事项)）。

## 11. Ship-to 申请

Ship-to 是创建后**不可修改**的目的地址主数据（唯一编号为 **Account ID**）。目的地址变化时应申请新的 Ship-to，不更新原记录。

### 11.1 新增申请

快速记录 → **Ship-to 申请**：

1. **客户名称**（默认当前项目客户）与新址地址（必填）。
2. **推进到**：待提交 / 处理中 / 已完成（线性流转，不支持退回或取消）。
3. 点 **保存记录**。

### 11.2 给已有申请补 Account ID 并完成

表单顶部「已有 Ship-to 申请」选择器：

- 用 **查找**（输入客户名称或新址）在分页列表中查找申请。
- 选中某个既有申请后，客户名称与新址地址被锁定，只需填写 **Account ID** 后保存，申请即进入「已完成」。

### 11.3 状态与工作量

- 状态线性流转：待提交 → 处理中 → 已完成；不支持退回或取消。
- 每条申请**首次实际提交**计一次工作量；待提交草稿不计。
- 申请只记录客户名称与新址地址，不关联搬迁仪器，不保存地址快照。
- 未完成的申请只作为「Ship-to 待处理」提示展示，不阻塞项目流转。

## 12. 序列号地址更新

逐台搬迁仪器记录其序列号**实际关联地址**的事实（客户名称、新址地址、序列号、Account ID 与更新日期）。项目地址只是默认值，逐台更新记录才是实际关联事实；本模块**不创建、不修改、不删除** Ship-to 主数据。

### 12.1 操作步骤

1. 顶部导航点击 **序列号地址更新**，打开独立模块抽屉。
2. 先在项目队列选择项目（提示：请先在项目队列选择项目，再从该项目的仪器分页中选择），左侧表单出现「搬迁仪器」选择器（必填，分页读取）。
3. 填写：**客户名称**（默认当前项目客户）、**新址地址**、**序列号**、**Account ID**（均必填）、**更新日期**（默认当天）。
4. 点 **保存记录**。
5. 右侧列表可 **查找记录** 并分页查看（显示客户名称 / 序列号 · Account ID / 更新日期）。

## 13. 服务二维码与二维码申请

工作台**不保存二维码地址**，只做两件事：

### 13.1 按仪器手工标记「二维码是否申请」

录入搬迁仪器时（快速记录 → 搬迁仪器），「二维码是否申请」选择是 / 否，由负责人按仪器手工标记。

### 13.2 二维码申请（独立模块）

1. 顶部导航点击 **二维码申请**。
2. 填写**申请人**（必填）、**申请日期**（默认当天，必填）。
3. 勾选**申请类型**（必填，可多选）：
   - **仪器服务**
   - **项目验收单**
   - **物流管理**
4. 点 **保存记录**。

规则：

- 申请不关联搬迁仪器或搬迁项目，**不设状态流转**。
- 工作量按申请记录 × 去重后的选中类型各计一次，按申请日期所属月份归属统计。
- 当前界面只提供上述 3 类申请类型（历史数据中有无法还原的类型，见 [20](#20-当前界面限制与未验证事项)）。

## 14. 损坏/维修事项

一台搬迁仪器的一次运输损坏及其后续处理，作为一个「损坏/维修事项」整体记录。**一个事项只对应一个备件**；多个备件请分别建立事项。

### 14.1 登记与字段

快速记录 → **损坏/维修事项**：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| 损坏原因 | 必填 | |
| 备件号 | 必填 | 单个备件 |
| 数量 | 必填 | ≥ 1 |
| 备件金额 | 必填 | 大于 0 |
| 币种 | 选择 | RMB / USD（RMB 按固定汇率 1 USD = 7.2 RMB 折算 USD 参与统计） |
| 备件状态 | 选择 | 待提交 / 处理中 / 已到件 / **已使用**（仅"已使用"计入维修费用与合同占比） |
| 事项处理状态 | 选择 | 未处理 / 维修中 / 已修复 / 未修复关闭 |
| 登记日期 | 必填 | |

### 14.2 限制

- **合同 USD 含税金额为空或为 0 时**：可以登记损坏，但禁止开始 / 完成维修、禁止将备件标记为"已使用"；补齐正数合同金额后才允许。
- 未完成维修不阻塞验收、掉票或完成流转；验收后仍可继续登记和维修。

## 15. 运营报表

顶部导航点击 **运营报表**，打开报表抽屉。报表为**手工月份区间 + 实时计算**，不保存历史快照。

### 15.1 筛选与计算

1. 选择**起始月份**与**截止月份**（格式为月份，必填，无默认季度）。
2. 点击 **实时计算报表**。

> 当前界面筛选**只有月份区间**；区域、开单类型、运输公司、工程师、责任人等维度在指标口径中保留但暂未在报表界面开放（见 [20](#20-当前界面限制与未验证事项)）。

### 15.2 报表小节与下钻

计算后展示报表小节（每个小节显示行数）：

- 项目管道
- 各区域新项目进单金额
- 月度掉票
- 月度开单量
- 损坏维修统计
- 月度物流费用
- Ship-to 申请工作量
- 二维码申请工作量
- 序列号地址更新记录数

每个小节有 **查看明细** 按钮：点击后在本界面下方显示该指标的明细行（下钻明细与指标口径一致）。

### 15.3 导出

底部三个导出按钮：**导出 Excel**（.xlsx）· **导出 PNG** · **导出 PDF**。

- 导出内容 = **当前筛选条件下的实时结果**，与界面实时计算结果一致。
- 导出成功有反馈；取消保存对话框或导出失败会就地提示，不会静默成功。
- 不支持 CSV 导出（规格只提供三种格式）。

## 16. 备份与恢复

所有业务数据都在本机 SQLite。备份是防丢失的第一道防线。

### 16.1 每日自动备份

- 每日首次使用且当天尚无自动备份时，自动创建 `auto-YYYY-MM-DD.db`。
- 自动备份**只保留最近 7 份**，更旧的自动清理；手动备份不受数量限制。
- 自动备份失败时：登录页和工作台顶部显示「自动备份失败：…」警告，工作台仍可正常使用，请尽快手动备份。

### 16.2 手动备份

顶部 **数据管理** → **手动备份** → 在文件对话框中选择目标目录 → 保存。成功后显示「手动备份已保存」。

### 16.3 恢复备份

顶部 **数据管理** → **恢复备份**：

1. 弹窗确认：「恢复备份会替换当前本地数据并要求重新登录。是否继续？」→ 确定。
2. 选择要恢复的备份文件。
3. 恢复前会校验备份可读；备份损坏 / 不可读时**停止恢复、不覆盖当前数据**，并明确报错。
4. 恢复成功后会**要求重新登录**（恢复前会自动创建安全快照，恢复过程为原子替换）。
5. 恢复后建议立即登录核对业务数据，并做一次手动备份。

## 17. 历史数据导入：七步向导

> 历史数据导入的**唯一入口**是登录工作台后 **数据管理 → 历史数据导入**，不存在外部命令行入口。

导入不会在确认前写入任何业务数据：先在独立草稿中整理、校验，最后按封存计划**整体提交**（任一记录失败，本次全部数据都不会保存）。

### 17.1 首页：新建或继续草稿

- 点击 **新建导入** 创建草稿。
- 已有草稿显示卡片：保存状态（已保存 / 保存中 / 保存失败）、上次停在的步骤、记录数、问题数、更新时间。
  - **继续草稿**：回到上次保存的步骤继续。
  - **删除草稿**：需确认（「删除这份导入草稿？现有业务数据不会受到影响」），只删除工作区，不影响业务数据。
- 如果上次提交曾中断，首页顶部出现「上次提交曾中断」提示，需先核对最终结果再决定下一步。

### 17.2 七步流程

左侧步骤栏（也可点「上一步 / 下一步」）：

| 步骤 | 名称 | 内容 |
| --- | --- | --- |
| 01 | **准备数据** | 模板、文件与列映射 |
| 02 | **项目与合同** | 按 ECC 聚合 |
| 03 | **开单记录** | 四类服务单据 |
| 04 | **掉票与物流费用** | 金额与发生日期 |
| 05 | **序列号地址更新** | 逐台实际地址 |
| 06 | **二维码与 Ship-to 申请** | 独立申请记录 |
| 07 | **校验摘要与确认** | 封存后整体提交 |

### 17.3 准备数据（01）

- **下载 Excel 模板**：下载当前版本空白模板（七类工作表 + 填写说明，不含示例业务行）。
- **选择一个或多个文件**：选择 `.xlsx` 文件，读取与规范化在独立工作线程执行，可取消。
- 「文件与工作表」清单：为每个工作表指定**目标类别**（七类之一）或 **明确排除**。
- 「列映射」：核对源列 → 目标字段，处理别名与来源优先级（精确匹配 / 已知别名 / 待人工选择 / 不使用）。
- 也可以不选文件：在后续目标网格中**直接从 Excel 粘贴**。

### 17.4 七类声明与网格编辑（02–06）

每个步骤内按类别切换；每个类别必须显式声明：

- **有数据**：进入可编辑目标网格。
- **本次不导入**：不生成虚拟行、默认业务事实或待补记录，可继续下一步。

网格操作：

| 按钮 | 作用 |
| --- | --- |
| **新增空白行** | 手工补录 |
| **删除选中行** | 删除选中的草稿行 |
| **从 Excel 粘贴** | 从 Excel 矩形区域复制后粘贴；弹窗确认第一行是「字段表头」还是「业务数据」；开始前会建立可恢复检查点，可取消，完成后可撤销整体恢复 |
| **撤销 `Ctrl Z` / 重做 `Ctrl Y`** | 撤销 / 重做当前会话操作 |

### 17.5 问题面板：错误 / 冲突 / 警告

右侧「问题」面板按级别计数：**错误 / 冲突 / 警告**。每条问题显示类别、行号、字段与来源；**定位** 跳到对应网格单元格，**处理冲突** 打开冲突对话框。

- **错误**：必填缺失、缺 ECC、序列号不匹配等 → **阻断**，不解决不能提交。
- **冲突**：多来源对同一字段给出不同合法值 → 弹窗选择保留哪个来源的值，或直接输入修正值；重复的非空服务单号也进入冲突清单，解决前该批次禁止提交。冲突决定保存后问题消除。
- **警告**：如"仅按位置识别身份"的提醒、物流成交价高于合同预算价等 → 不阻断，但提交前需要确认。
- 键盘：`F8` 定位下一条阻断问题。

### 17.6 校验与封存（07）

- 进入第 7 步后，先点 **开始完整校验**（可取消）。校验重新检查七类数据、ECC 关联和现有目标数据；**校验阶段不写入任何业务数据**。
- 通过后生成「计划已封存」：seal 绑定计划摘要、规则版本、目标库身份与业务修订。**任何草稿修改、规则 / schema 升级、目标数据变化都会使封存失效**，需点 **重新完整校验**。
- 摘要表：各类别的新增 / 匹配现有 / 修正 / 幂等跳过 / 警告 / 阻断数；以及 ECC 聚合项目、独立记录、排除来源与金额合计。
- 提交前勾选：「我已核对七类记录范围、金额和排除来源」；存在警告时还需勾选「我已查看并确认 N 条警告」。
- 点 **确认导入** → 弹窗「确认整体导入」（说明：任一记录失败，本次全部数据都不会保存）→ **开始导入**。
- 提交期间界面提示「正在整体提交 · 当前只有一个提交任务，请不要关闭窗口」。

### 17.7 原子提交与失败恢复

- 提交为**单个立即写事务**：七类数据 + 来源审计 + 目标快照 + 成功审计 + 对账一次写入；任一步失败**整体回滚，零部分写入**。
- 提交前事务外创建并验证安全快照（快照失败则零业务写入）。
- **中断恢复**：
  - 提交中断后，首页出现「上次提交曾中断」→ 点 **核对 × 的最终状态**。
  - 结果页三选一：「整批导入已完整成功」「整批导入已完整回滚」「提交结果仍需核对」（可再核对一次）。
  - 完整回滚后草稿保留，但旧封存失效，进入草稿后必须**重新完整校验**才能再次提交。
  - 解析 / 校验中断：重启后回到最后稳定修订。
- 运行审计记录登录账号内部 ID、提交时用户名快照、计划摘要、规则版本、七类计划与写入数；导入的业务事实标记为**历史导入来源**，不计入当前账号的手工工作量。

## 18. 常见报错与问题排查

### 18.1 登录与账号

| 现象 | 原因与处理 |
| --- | --- |
| 登录状态已失效 | 会话过期，回到登录页重新登录即可。导入向导中最后一次成功保存的草稿仍保留，重新登录后需重新完整校验 |
| 忘记密码 | 登录页「忘记密码？使用恢复码」→ 输入离线保存的恢复码与新密码重置（见 [2.4](#24-忘记密码使用恢复码重置)） |
| 自动备份失败警告 | 当天自动备份未成功；不影响使用，请尽快手动备份 |

### 18.2 项目与状态

| 现象 | 原因与处理 |
| --- | --- |
| 「已取消项目不可恢复；如需继续工作需重新新增项目」 | 已取消是终态 |
| 「存在任何掉票历史（含已撤销掉票）的项目禁止取消」 | 有掉票记录（含已撤销）的项目不能取消 |
| 「无法直接调整为已完成：无 0 金额闭环，须先录入大于 0 的最终可确认金额」 | 调为已完成前必须录入大于 0 的最终可确认金额 |
| 「累计掉票金额尚未达到最终可确认金额」 | 累计掉票未达标，继续登记掉票后再调整 |
| 「未进单先执行标签存在时主状态保持待进单」 | 未进单先执行项目先完成正式进单再调整状态 |
| 同一搬迁项目内非空序列号重复 | 序列号在同一个搬迁项目内不得重复；确认后修改其一 |

### 18.3 记录与保存

| 现象 | 原因与处理 |
| --- | --- |
| 保存提示金额必须大于 0 | 除合同 USD 含税金额外，最终可确认、掉票、报价、物流、备件金额有值必须 > 0 |
| 物流成交价高于合同预算价（黄色提示） | 允许记录；如确认差额无问题，直接保存 |
| 填写服务单号但未填工程师 | 开单记录中填写服务单号时必须同时填写执行工程师，否则拒绝保存并就地提示 |
| 二维码申请提示「请至少选择一种二维码申请类型」 | 申请类型必填，可多选 |
| 合同金额为 0 时维修受限 | 合同 USD 含税金额为空或 0 时禁止开始 / 完成维修、禁止备件标记"已使用"；补齐正数合同金额后恢复 |

### 18.4 导入向导

| 现象 | 处理 |
| --- | --- |
| 封存失效（计划未封存） | 草稿或目标数据已变化，点 **重新完整校验** 后再提交 |
| 阻断项未解决 | 错误 / 冲突不解决不能提交；`F8` 逐条定位，冲突用「处理冲突」选择或修正 |
| 导入未完成 | 本次没有产生部分导入，草稿已保留；重新完整校验后再提交 |
| 提交中断 | 首页「上次提交曾中断」→ 核对最终状态（成功 / 回滚 / 需再核对） |
| 保存失败（草稿卡片） | 稍后重试；草稿数据未丢失（乐观修订，重启恢复到上次稳定保存） |
| 模板 / 导出保存被取消 | 提示「已取消保存」，未生成文件，重新操作即可 |

### 18.5 报表

| 现象 | 处理 |
| --- | --- |
| 导出取消或无反应 | 提示「已取消保存，未生成导出文件」或导出失败就地提示；重新导出 |
| 无 CSV 选项 | 规格只提供 Excel / PNG / PDF 三种导出 |

> 数据损坏（数据库打不开等）：停止使用，用最近一次可用备份恢复（见 [16.3](#163-恢复备份)）。

## 19. 数据与安全边界

| 边界 | 说明 |
| --- | --- |
| 数据位置 | 全部业务数据保存在本机 SQLite（`data/workbench.db`），关闭重开保留 |
| 不联网 | 不接远程数据库、云同步或外部业务系统，不向远程服务发送业务数据 |
| 本地账号 | 只是应用访问门槛，**不加密 SQLite**；直接读取数据库文件不受账号保护 |
| 主要保护边界 | 数据文件与备份由 **Windows 操作系统账户**、文件系统 ACL 与磁盘加密（如 BitLocker）保护 |
| 备份 | 每日自动备份（保留最近 7 份）+ 手动备份；恢复前校验可读、失败不覆盖 |
| 恢复码 | 一次性恢复凭据，建议与数据库备份分开存放 |
| 密码与恢复码存储 | 不以明文存储（scrypt + 随机盐 + 恒定时间比较） |
| 账号数量 | 仅一个本地账号，不支持多账号、注册、角色与权限管理 |
| 工作量归属 | 手工录入事实与工作量归属当前登录账号（持久化账号内部 ID 与用户名快照，改名不影响历史统计）；历史导入的数据不计手工工作量 |

| 无外部命令行入口 | 历史数据导入只有工作台内向导一个入口；早期迁移 CLI 已移除 |
| 单一账号 | 不支持第二个账号、注册、角色或权限管理 |

## 21. 日常操作建议

1. **先提醒后队列**：每天从「项目提醒快速处理」开始，处理已逾期与今日到期的提醒，再连续推进项目队列。
2. **善用就近记录**：选中项目后，行内「记录」、上下文「快速记录」、详情页「就近记录」都能快速录入，不用反复打开新建向导。
3. **及时记录验收与金额**：录入验收报告形成日期会自动进入待掉票；登记最终可确认金额后再登记掉票，接近金额闭环时系统会自动流转到已完成。
4. **批次费用一次记录**：创建搬迁批次时同时填写费用登记日期、合同预算价与物流成交价（人民币），物流成交价即最终实际物流费用，并核对物流成交价与合同预算价的关系。
5. **每周手动备份**：自动备份只有最近 7 份；重要节点（大批导入、季度统计前）再做一次手动备份。
6. **恢复码分级保存**：恢复码离线保存，不与数据库备份放一起。
7. **导入前先备份**：执行历史数据导入前做一次手动备份；导入后核对 ECC 聚合项目数与业务数据。
8. **季度汇报用报表**：运营报表按月份区间实时计算并导出 Excel / PNG / PDF，下钻明细可用于核对口径。
