# 新增搬迁服务工作台

## Why

搬迁服务工作台尚无任何规格。业务方已提供《搬迁服务工作台 · 需求规格》v0.2（docs/搬迁服务工作台.md）作为首版需求基准，其中客户已确认的规则为权威业务规则，领域术语以 CONTEXT.md《搬迁服务》为准。

工作台的目标是让搬迁负责人从进单、联系客户、安排运输公司与工程师、录入单据、记录执行状态到费用申请完成全流程控制，同时记录关键时间点、把控项目流程、回顾工作情况，并按各业务对象（开单、Ship-to 申请、损坏维修备件、二维码申请、序列号地址更新、掉票等）的工作量支撑季度汇报类统计报表。

需求规格正文已明确首版范围、角色边界、领域对象关系、生命周期主状态、各子流程、金额币种规则、统计指标口径与存量迁移原则。经客户确认，TBD-07/10/11/18 已解决（另有 TBD-16 先前已解决），剩余 20 项尚无业务结论、当前高风险未决 0。为使首版规格可实施，本 change 为这 20 项给出首版推测（暂定决定，仅规划用），并据此规划 14 个能力规格的路径（含新增 serial-address-update）；后续允许通过本 change 修订暂定决定，不得将其视作业务方已确认。工作台信息架构（任务指挥台结构）、数据录入方式与视觉可用性基线已由客户高保真录入原型选择确认，不属于 TBD 暂定范围；高保真原型后续将更新但仍非生产实现。运行与持久化边界（仅 Windows 桌面、Electron + React + TypeScript、本地 SQLite、无远程集成、依赖 Windows 操作系统账户、自动/手动备份恢复）已确认，TBD-16 相应标记为已解决。

本 change 仅做规划，不包含任何代码实现。

## What Changes

### 已确认范围（来自需求规格正文）

- 首版记录搬迁、认证、单寄备件、PM 四类开单业务及各自工作量；只有搬迁业务建立搬迁项目，进入完整的进单、执行、验收、掉票生命周期；认证、单寄备件与 PM 开单独立保存，不进入搬迁项目生命周期。
- 首版仅搬迁负责人使用并维护工作台数据；应用无应用内登录/账号体系，访问依赖 Windows 操作系统当前用户账户（见运行与持久化边界）；经理批复、工程师执行、运输公司信息、合同金额等外部事实由负责人手工记录，系统自动记录或迁移导入的数据不视为手工录入；不保留项目负责人字段，不做多人账号与数据权限控制。
- 项目主状态依次为待进单、待执行、执行中、待验收、待掉票、已完成；终止的项目标记为已取消；“未进单先执行”作为独立标签与主状态并存。
- 已确认的状态转移：待进单→待执行（正式进单且尚未发生实际执行活动）；待执行→执行中（首次上门活动开始或首个搬迁批次开始运输）；执行中→待验收（录入实际装机完成时间，计划装机时间不触发，TBD-07 已解决）；待验收→待掉票（标记已有验收报告并填写报告形成日期，不需要客户确认）；待掉票/已完成之间按累计掉票金额与项目最终可确认金额闭环重算（录入金额有值必须 > 0、无 0 金额闭环，TBD-11 已解决）。
- 进单与开单是两个独立业务事件；进单时间以搬迁负责人确认接手时间为准；开单工作量按唯一服务单号计数，一个搬迁项目可关联多条开单记录；进单向导中录入单号时，参与工程师必填——填写单号但未选定参与工程师则拒绝保存整个向导并就地提示，填写且已选定参与工程师时项目与自动创建的对应开单记录同次保存（生成日期默认当前日期、备注可空）。
- 物流模型分两层：批次报价层记录计划运输日期、运输公司与人民币原价、折后价（有值必须 > 0）；物流费用记录层记录登记日期（必填默认当天）、预算价格、成交价格与物流费用（人民币，三项必填且大于 0），成交价格大于预算价格时警告但允许保存，不生成标准待办、不阻塞批次运输或项目流转；系统展示成交价格与实际物流费用的差异。
- 搬迁项目设置项目默认地址；搬迁仪器默认沿用项目默认地址，并可通过序列号地址更新逐台记录实际关联地址（见 serial-address-update 能力）；实际仪器地址只由序列号地址更新表达。Ship-to 创建后不可修改，唯一编号沿用现有字段名 Account ID；目的地址变化时重新申请新的 Ship-to。Ship-to 申请仅记录客户名称与新址地址，不关联搬迁仪器、不保存地址快照；申请创建时 Account ID 可空，由系统外完成流程返回后由负责人补入全局唯一的 Account ID（补入后进入已完成并记录完成时间，完成前 Account ID 必填）；申请采用待提交、处理中、已完成、已取消独立状态，每条申请首次实际提交计一次工作量，待提交草稿不计，退回重提不重复计数；申请未完成只显示为独立待办，不阻塞项目流转。
- 损坏/维修事项合并记录一台搬迁仪器的一次运输损坏及其后续处理（单个备件，不再设独立备件申请），独立于搬迁项目生命周期，未完成维修不阻塞验收、掉票或完成；事项状态为未处理、处理中、已修复、已关闭未修复（关闭未修复必须记录原因）；备件金额保留原币（仅 USD/RMB），RMB 按固定 1 USD = 7.2 RMB 折算为 USD 参与统计，首版不接入实时汇率。
- 服务二维码为独立模块：按搬迁仪器分别对应，内容为公司统一定制；工作台不保存二维码 URL，由负责人按仪器手工标记“二维码是否申请”（是/否），该标记不自动生成任何标准待办，不阻塞上门、运输或状态流转；二维码申请为独立申请记录（申请人、申请时间、多选九类类型），不关联搬迁仪器或搬迁项目，申请工作量按申请记录 × 去重后的选中类型计数，按申请时间所属月份归属。
- 待办与提醒：系统按缺失信息和项目流程阶段自动生成标准待办（清单仅限七类，见 TBD-23），负责人可新增自定义待办；标准待办在业务条件满足后自动完成，自定义待办手工完成或取消；仪器“二维码是否申请”为手工标记，不自动生成任何标准待办；首版仅在工作台内展示提醒，不接入邮件、企业微信等外部渠道；临期范围可由负责人配置，未配置时默认未来 7 个自然日，截止日当天为今日到期，超过为已逾期。
- 取消规则（TBD-10 已解决）：任何无掉票历史（含撤销）的未取消主状态项目均可取消；存在任何掉票历史（含撤销记录）的项目禁止取消；取消不可恢复，取消必须记录取消时间与原因并保留已发生的上门活动、物流与费用记录；取消期间禁止修改合同金额、最终可确认金额与掉票记录；已取消项目排除收入/掉票相关指标，真实物流/备件成本保留并标记为取消。
- 金额与币种：合同 USD 含税金额由负责人手工录入，不按净值与税率自动计算，不一致时警告但允许保存；正式进单时保存合同金额快照，后续合同变更不改写历史进单金额；项目最终可确认金额默认取合同 USD 含税金额，调整必须记录原因；录入金额有值必须大于 0，不允许 0 或负数，无 0 金额闭环（TBD-11 已解决）；新增掉票后累计金额不得超过最终可确认金额；物流费用以人民币记账；备件金额仅 USD/RMB，RMB 备件金额固定按 1 USD = 7.2 RMB 折算为 USD。
- 统计指标：各区域新项目进单金额（进单时间归属）、月度掉票金额与掉票次数（掉票时间归属）、月度开单量（服务单号计数，按四类业务分组）、损坏维修记录数量与单备件金额及合同占比、月度物流费用（人民币，按实际物流费用登记日期归属、按运输公司汇总）、待补实际费用清单（已有成交但未登记实际物流费用的批次）、Ship-to 申请工作量、二维码申请工作量（独立统计）、序列号地址更新记录数。
- 存量数据迁移（TBD-18 已解决）：首版一次性导入现有 Excel 中可明确映射的历史记录，由工作台外部署运维人员执行；多来源字段冲突不自动覆盖，生成冲突清单由负责人确认；dry-run 对目标必填字段缺失（含物流费用记录登记日期）输出源文件、sheet、行与字段错误，由客户修改源 Excel 或补录模板后重跑，正式导入前不得存在任何错误；批次内任一目标必填字段缺失错误则该批次整批不写入、不产生部分导入；正式事务导入（每批次整体提交或整体回滚），导入后不存在待补必填字段，不建补录 UI，不提供持续导入功能；可选字段允许为空，不用导入时间替代可选源业务时间。
- 运行与持久化边界（已确认，TBD-16 已解决）：仅个人使用、仅 Windows 桌面应用（Electron + React + TypeScript）；全部业务数据持久化在本机 SQLite，关闭重开保留；不接远程数据库、云同步或外部业务系统，不向远程服务发送业务数据；无应用内登录/账号体系，依赖 Windows 操作系统账户保护本机数据；每日首次使用时自动备份并仅保留最近 7 份自动备份，支持立即手动备份到所选本地目录与从所选本地备份恢复（恢复前确认并验证可读，失败不覆盖当前数据），备份/恢复失败给出明确错误；数据结构升级通过迁移保留现有本地数据，迁移失败保留可恢复状态。对应新增能力 local-data-persistence，并记录于 ADR `docs/adr/0001-windows-desktop-local-sqlite.md`。
- 工作台信息架构与数据录入方式已通过高保真录入原型选择确认（客户决定以 A「任务指挥台」为主，保留 B 的「生命周期吞吐」板块和 C 的「当前上下文」板块；选定原型 `prototype/relocation-workbench/selected/relocation-workbench-selected.html` 已升级为高保真录入原型，是设计依据，不是生产代码，后续将更新）：待办快速处理与高密度项目队列是主操作流；生命周期吞吐是紧凑全局节奏视图（六阶段项目数、平均停留、流入流出与瓶颈提示，可点击筛选项目队列）；当前上下文是随选中项目/待办/阶段联动的常驻侧栏（状态与异常、下一步待办、金额闭环、Ship-to/二维码/损坏维修等非阻塞事项）；项目总览、搬迁仪器、搬迁批次、上门活动、费用与掉票、申请与维修六个详情 tab 按需展开。数据录入为已确认界面要求：新建搬迁项目采用四步向导（基本信息、搬迁范围、执行准备、确认方式），提供保存为待进单、正式进单、未进单先执行三个确认路径，向导录入单号时参与工程师必填（未选定工程师拒绝保存整个向导并就地提示），填写且已选定工程师时项目与自动创建的对应开单记录同次保存（生成日期默认当前日期、备注可空）；留空的可后补字段仅在满足 workbench-todos 既有七类逐类规则时生成对应标准待办，不承诺任意向导空字段都有待办；当前项目通过快速记录就近录入搬迁批次、搬迁仪器、上门活动、开单记录、实际物流费用、验收报告、掉票、Ship-to 申请、损坏/维修事项、补齐进单核心资料等业务动作（二维码申请与序列号地址更新为独立模块，不进快速记录），项目队列、当前上下文与详情 tab 均提供就近入口；点击待办直达对应表单；视觉采用高可读企业运营风格，具备合理字号、间距、层级与表单反馈（Modal/Drawer/Toast、必填/可后补标识、校验反馈、键盘焦点与 Escape 关闭）。以上均为客户确认的界面决策，不属于 25 项 TBD 暂定范围。
- 明确不做（Non-goals），分为三类：
  - **已确认不做**（来自需求规格正文与已确认边界）：多人账号与数据权限控制；项目负责人字段；销售通知时间记录；邮件自动解析与外部消息渠道提醒；二维码生成与外部页面实现及二维码 URL 保存、二维码自动待办；实时汇率服务；财务审批、驳回与客户回款状态追踪；验收报告附件或外部链接存储；认证、单寄备件与 PM 的完整生命周期；独立备件申请流程（并入损坏/维修事项）；远程数据库、云同步与外部业务系统集成（TBD-16 已解决）；应用内登录、注册、密码与角色权限体系（无应用内账号体系，访问依赖 Windows 操作系统账户）。
  - **暂定 Non-goals**（TBD-17 暂定，未经业务确认，不得视为已确认）：月结与报表快照（TBD-17）；Excel/PDF 导出（TBD-17，首版仅 CSV）；补录 UI（TBD-18 已解决，迁移错误行不导入，客户修改源 Excel/补录模板后重跑，不建补录 UI）。
  - **纯技术设计 Non-goals**（不界定业务范围，仅约束实现路线）：通用工作流、规则引擎与事件溯源。

### 暂定决定

以下 20 项为 TBD-01~25 中除已解决的 TBD-07/10/11/16/18 外的首版推测，仅用于让首版规格可实施；均为暂定、未经业务方确认，后续允许通过本 change 修订。括号内为风险评级：当前高风险未决 0 项；中风险（01/02/03/05/06/08/09/12/13/14/19/20/21/23/25）、低风险（04/15/17/22/24）。

1. TBD-01（暂定，风险：中）待进单时同步建立不完整的合同草稿；系统分配稳定的内部 ID 与临时编号；正式进单时补充唯一 ECC，内部 ID 与临时编号保留；正式进单后 ECC 允许纠错修改，但须保持全局唯一并记录最后修改时间。
2. TBD-02（暂定，风险：中）暂定数量不生成假仪器；需要提前关联时可建立无序列号占位项；非空序列号在项目内唯一、跨项目可重复。
3. TBD-03（暂定，风险：中）仪器在运输开始前可以无批次或改批且不留历史；运输开始后禁止直接改批；批次开始运输时至少有一台仪器，且参与运输的仪器必须明确归属该批次。
4. TBD-04（暂定，风险：低）Ship-to 申请仅记录客户名称与新址地址，不关联搬迁仪器、不保存地址快照；Account ID 创建时可空、系统外完成后补入且完成前必填，补入后创建/关联不可变 Ship-to 并进入已完成；实际仪器地址仅由序列号地址更新表达；其余实现细节（如申请状态流转边界）待评审确认。
5. TBD-05（暂定，风险：中）上门活动可包含多个工作类型；工作事实记录在“活动 × 仪器 × 工作类型”粒度；工作事实采用两态持久化：不存在对应工作事实即表示未开始，创建事实时状态为进行中并记录开始时间，完成后状态为已完成并记录完成时间；“未开始”不作为工作事实的持久化状态，但仪器拆装进度仍可展示为未开始/进行中/已完成，由工作事实是否存在及其状态推导，不以仅存在工作事实记录即视为完成。
6. TBD-06（暂定，风险：中）九类二维码类型先作为固定代码，仅用于分类与工作量计数；二维码申请为独立申请记录，记录申请人、申请时间与一个或多个（多选）申请类型，申请记录不关联搬迁仪器或搬迁项目；工作量按申请记录 × 去重后的选中类型计数（同一条记录内相同类型只计一次、不同申请中的相同类型分别计数），按申请时间所属月份归属；重复申请保留历史；工作台不保存二维码 URL，由负责人按仪器手工标记“二维码是否申请”（是/否），该标记不自动生成任何标准待办。
7. TBD-07（已解决，2026-08-07 客户确认）执行中→待验收由录入实际装机完成时间触发，计划装机时间不触发进入待验收；未完成项仅警告不阻塞。详见《已确认范围》状态转移，不再属于未决暂定项。
8. TBD-08（暂定，风险：中）存在“未进单先执行”标签时主状态保持待进单；正式进单后按已有事实跳到待执行、执行中或待验收。
9. TBD-09（暂定，风险：中）主状态由业务事实和动作推导，不可直接编辑。
10. TBD-10（已解决，2026-08-07 客户确认）任何无掉票历史的未取消主状态项目均可取消；任何掉票历史（含撤销记录）的项目禁止取消；取消不可恢复；取消期间禁止修改合同金额、最终可确认金额与掉票记录；已取消项目排除收入/掉票相关指标，真实物流/备件成本保留并标记为取消。详见《已确认范围》取消规则，不再属于未决暂定项。
