# 新增搬迁服务工作台

## Why

搬迁服务工作台尚无任何规格。业务方已提供《搬迁服务工作台 · 需求规格》v0.3（docs/搬迁服务工作台.md）作为首版需求基准，其中客户已确认的规则为权威业务规则，领域术语以 CONTEXT.md《搬迁服务》为准。

工作台的目标是让搬迁负责人从进单、联系客户、安排运输公司与工程师、录入单据、记录执行状态到费用申请完成全流程控制，同时记录关键时间点、把控搬迁项目流程、回顾工作情况，并按各业务对象（开单、Ship-to 申请、损坏维修备件、二维码申请、序列号地址更新、掉票等）的工作量支撑季度汇报类统计报表。

客户已就 TBD-01~25 全部给出最终答复（2026-08-07），剩余未决=0、高风险=0，不再存在"暂定决定、按模块复核、可评审调整"口径；单一本地应用账号访问边界（TBD-16 修订）继续有效。本 change 据此规划 15 个能力规格的路径（其中历史数据导入由 historical-data-import 与 history-import-wizard 两个能力共同覆盖：前者定义规范化、校验、幂等、原子提交与审计的领域语义，后者定义登录后的工作台内导入向导体验）。工作台信息架构（任务指挥台结构）、数据录入方式与视觉可用性基线已由客户高保真录入原型选择确认；主工作流为"项目提醒快速处理 + 高密度项目队列"。运行与持久化边界（仅 Windows 桌面、Electron + React + TypeScript、本地 SQLite、单一本地应用账号、自动/手动备份恢复）已确认。

本 change 仅做规划，不包含任何代码实现。

## What Changes

### 已确认范围（来自需求规格正文与客户最终答复）

- 首版记录搬迁、认证、单寄备件、PM 四类开单业务及各自工作量；只有搬迁业务建立搬迁项目，进入完整的进单、执行、验收、掉票生命周期；认证、单寄备件与 PM 开单独立保存，不进入搬迁项目生命周期。认证/单寄备件/PM 开单至少记录开单时间、服务单号、开单类型、工程师、客户单位，备注可选，开单时间未填默认当前时间。
- 首版仅搬迁负责人使用并维护工作台数据；应用提供**单一本地应用账号**作为访问门槛——首次启动必须创建用户名与密码，创建后禁止新增第二个账号，不支持多账号、注册、自助新增用户、角色或权限管理；后续启动需登录该本地账号，无远程认证、外部身份源或账号同步；忘记密码可通过首次创建时生成的一次性恢复码重设（恢复码只展示一次、由用户离线保存，使用后失效并生成新恢复码）。密码与恢复码不以明文存储（Node 内置 scrypt + 每条记录随机盐 + 恒定时间比较，不引入原生密码依赖）。本地账号仅为应用访问门槛、不加密 SQLite，Windows 操作系统账户仍是本机数据文件与备份的主要保护边界；手工录入事实与工作量责任人归属当前已登录的本地应用账号，动作记录持久化账号内部 ID 与当时用户名快照，历史统计不因以后改名而动态变化（本规则不因仅有一个账号而省略）。经理批复、工程师执行、运输公司信息、合同金额等外部事实由负责人手工记录，系统自动记录或迁移导入的数据不视为手工录入；不保留项目负责人字段，不做多人账号与数据权限控制。
- 项目主状态依次为待进单、待执行、执行中、待验收、待掉票、已完成；终止的项目标记为已取消；"未进单先执行"作为独立标签与主状态并存。负责人可直接选择/人工调整项目主状态（TBD-09），系统在保存时校验合法状态、取消约束与金额闭环约束；以下自动触发仍生效且人工选择不得覆盖：实际装机完成时间自动进入待验收（TBD-07）、验收报告自动进入待掉票、掉票金额闭环自动在待掉票/已完成之间重算。未进单项目与已进单项目在界面中使用明确不同的颜色/视觉标识（TBD-08）。
- 待进单阶段合同可空（可不关联合同），正式进单前必须补齐合同；系统不强制在待进单时创建空合同草稿，项目稳定内部 ID 与系统临时编号仍保留（TBD-01）。正式进单至少关联合同、客户单位并明确搬迁范围，任一缺失拒绝进单。进单与开单是两个独立业务事件；进单时间以搬迁负责人确认接手时间为准，进单时间必填、默认当前时间、允许补录修正。进单向导中录入单号时参与工程师必填——填写单号但未选定参与工程师则拒绝保存整个向导并就地提示，填写且已选定参与工程师时项目与自动创建的对应开单记录同次保存（开单时间默认当前时间、备注可空）。未进单先执行项目在正式进单后由负责人人工确定主状态，系统不按已发生事实自动跳转（TBD-08）。
- 物流模型分两层：批次报价层记录计划运输日期、运输公司与人民币原价、折后价（有值必须 > 0）；物流费用记录层记录物流费用申请（登记）时间（必填默认当天，决定归属月份，修改金额不改归属月份）、预算价格、成交价格与物流费用（人民币，三项必填且大于 0），成交价格大于预算价格时警告但允许保存，不自动创建项目提醒、不阻塞批次运输或项目流转；系统展示成交价格与实际物流费用的差异。新增"物流费用合同占比"：实际物流费用按固定汇率 1 USD = 7.2 RMB 折算为 USD ÷ 最新合同 USD 含税金额，合同金额为空或 0 时不可计算并提示（TBD-14）。
- 搬迁项目设置项目默认地址；搬迁仪器默认沿用项目默认地址，并可通过序列号地址更新逐台记录实际关联地址（见 serial-address-update 能力）；实际仪器地址只由序列号地址更新表达。Ship-to 创建后不可修改，唯一编号沿用现有字段名 Account ID；目的地址变化时重新申请新的 Ship-to。Ship-to 申请仅记录客户名称与新址地址，不关联搬迁仪器、不保存地址快照；申请创建时 Account ID 可空，由系统外完成流程返回后由负责人补入全局唯一的 Account ID（补入后申请进入已完成并记录完成时间，进入已完成前 Account ID 必填），补入的 Account ID 创建/对应不可变的 Ship-to；申请状态**线性流转**：待提交 → 处理中 → 已完成，不支持退回或取消（TBD-04）；每条申请首次实际提交计一次工作量，待提交草稿不计；申请未完成只作为独立提醒展示，不阻塞项目流转。
- 搬迁仪器必须登记仪器名称；非空序列号在同一合同/其唯一搬迁项目内不得重复、跨合同可重复；允许无序列号占位，暂定数量不生成虚拟仪器（TBD-02）。运输开始前允许无批次或改批，但每次改批保存改批历史（原批次、新批次、变更时间、登录账号归属）；运输开始后禁止直接改批（TBD-03）。
- 上门活动保留"活动 × 仪器 × 工作类型"模型（拆机、装机、维修、其他），在同一上门活动页面记录；拆机工作事实明确记录拆机状态及拆机开始/完成时间，其他工作类型记录各自状态与时间（TBD-05）。
- 损坏/维修事项合并记录一台搬迁仪器的一次运输损坏及其后续处理（单个备件，不设独立备件申请对象/入口），独立于搬迁项目生命周期，未完成维修不阻塞验收、掉票或完成；事项处理状态为未处理、处理中、已修复、已关闭未修复（关闭未修复必须记录原因）；备件新增"备件申请时间"与"备件处理状态"（待提交、处理中、已到件、已使用），仅"已使用"状态的备件计入维修费用与合同占比（TBD-13）；备件金额保留原币（仅 USD/RMB），RMB 按固定 1 USD = 7.2 RMB 折算为 USD 参与统计，首版不接入实时汇率。合同 USD 含税金额为空或 0 时，可登记损坏，但禁止开始/完成维修、禁止将备件标记为"已使用"，补齐正数合同金额后才允许（TBD-15）。维修上门活动与损坏/维修事项为多对多关联并保持仪器集合校验（TBD-24）。
- 服务二维码为独立模块：按搬迁仪器分别对应，内容为公司统一定制；工作台不保存二维码 URL，由负责人按仪器手工标记"二维码是否申请"（是/否），该标记不自动创建任何项目提醒，不阻塞上门、运输或状态流转；二维码申请为独立申请记录（申请人、申请时间、多选九类类型），不关联搬迁仪器或搬迁项目，**不设状态流转**（TBD-06），申请工作量按申请记录 × 去重后的选中类型计数，按申请时间所属月份归属。
- 待办与提醒：删除七类自动标准待办与自定义待办，改为**项目提醒**——搬迁负责人为每个搬迁项目手工维护一个当前提醒（当前提醒时间 + 备注内容），可编辑或清除、不保存提醒完成历史；系统不根据任何缺失字段自动生成提醒（TBD-23）；到期分类按提醒时间显示临期、今日到期或已逾期，临期窗口可配置、默认未来 7 个自然日；提醒仅在工作台内展示，不接入邮件、企业微信等外部渠道；主工作流为"项目提醒快速处理 + 项目队列"。
- 取消规则（TBD-10 已解决）：任何无掉票历史（含撤销）的未取消主状态项目均可取消；存在任何掉票历史（含撤销记录）的项目禁止取消；取消不可恢复，继续工作需重新新增项目；取消必须记录取消时间与原因并保留已发生的上门活动、物流与费用记录；取消期间禁止修改合同金额、最终可确认金额与掉票记录；已取消项目排除收入/掉票相关指标，真实物流/备件成本保留并标记为取消。
- 金额与币种（TBD-11/20）：金额最多两位小数、十进制定点、四舍五入、不得负数；仅"合同 USD 含税金额"允许为 0，其他录入金额（最终可确认、掉票、报价、物流、备件）有值必须大于 0，无 0 金额闭环；最终可确认金额不得低于累计掉票金额；合同金额为 0 时正式进单的最终可确认金额不能默认成 0，必须另行录入大于 0 的值；合同金额可直接覆盖当前值修改，不保存正式合同变更对象/历史、不要求原因（TBD-20），进单金额快照保持原值、最终可确认金额保持原值不随合同覆盖同步；新增掉票后累计金额不得超过最终可确认金额；物流费用以人民币记账；备件金额仅 USD/RMB，RMB 备件金额固定按 1 USD = 7.2 RMB 折算为 USD。掉票不可物理删除，撤销后为终态，禁止编辑、重复撤销或重新激活，更正需新增有效掉票（TBD-19）。
- 统计指标（TBD-12/13/14/17）：各区域新项目进单金额（进单时间归属、按进单金额快照）、月度掉票金额与掉票次数（掉票时间归属）、月度开单量（服务单号计数，按四类业务分组，开单时间归属）、损坏维修记录数量与单备件金额及合同占比（仅"已使用"备件计入）、月度物流费用（人民币，按物流费用申请/登记时间归属、按运输公司汇总）、物流费用合同占比（固定汇率折算 ÷ 最新合同 USD 含税金额）、待补实际费用清单（已有成交但未登记实际物流费用的批次）、Ship-to 申请工作量、二维码申请工作量（独立统计）、序列号地址更新记录数。报表月份区间由负责人手工选择（无默认季度）、实时计算、支持导出 Excel（.xlsx）、图片（PNG）与 PDF（导出当前筛选实时结果）；区域、开单业务类型、运输公司、参与工程师等筛选维度可保留。
- 存量数据迁移（TBD-18/21）：首版一次性导入现有 Excel 中可明确映射的历史记录；历史数据导入以**登录后的工作台内向导**为唯一入口（位于"数据管理"，与手动备份/恢复并列），由已登录负责人执行，不新增管理员账号或角色；以 ECC 为项目/合同聚合主键，同一 ECC 下全部执行数据聚合导入并作为一个搬迁项目展示；服务单号、Account ID、序列号用于子记录识别与冲突，不与 ECC 同级匹配项目；缺 ECC 的项目/合同执行数据在校验中报必填错误；向导提供版本化 Excel 模板下载、.xlsx 文件选择与 Excel 矩形区域复制粘贴，文件与粘贴数据进入同一规范化模型与可编辑目标网格，并在网格与问题面板中定位错误、冲突与警告；用户可保存并恢复独立导入草稿，校验阶段不写入任何业务表；多来源字段冲突不自动覆盖，生成冲突清单由负责人确认；迁移中发现不同源记录存在重复的非空服务单号进入冲突清单，解决前禁止提交；校验对目标必填字段缺失（含物流费用申请/登记时间）输出类别、字段、网格行与来源位置，由用户在向导内修正；正式提交前必须通过完整校验且不得存在任何错误；七类数据、来源审计、目标快照与成功审计在一次全局事务中整体提交或整体回滚，不产生部分导入；导入后不存在待补必填字段，不建补录 UI，不提供持续导入功能；可选字段允许为空，不用导入时间替代可选源业务时间；迁移运行审计归属最终确认的登录账号并保存确认时用户名快照，导入的业务事实标记为历史导入、不计作该账号的手工工作量；移除工作台外迁移 CLI、相关构建命令与"工作台不得提供导入入口"的旧约束，向导成为唯一历史数据导入入口。
- 运行与持久化边界（已确认，TBD-16 已解决）：仅个人使用、仅 Windows 桌面应用（Electron + React + TypeScript）；全部业务数据持久化在本机 SQLite，关闭重开保留；不接远程数据库、云同步或外部业务系统，不向远程服务发送业务数据；提供单一本地应用账号作为访问门槛（首次启动初始化、后续登录、恢复码重置，无多账号/角色/权限，无远程认证、外部身份源与账号同步）；本地账号不加密 SQLite，Windows 操作系统账户仍是本机数据文件与备份的主要保护边界；每日首次使用时自动备份并仅保留最近 7 份自动备份，支持立即手动备份到所选本地目录与从所选本地备份恢复（恢复前确认并验证可读，失败不覆盖当前数据），备份/恢复失败给出明确错误；数据结构升级通过迁移保留现有本地数据，迁移失败保留可恢复状态。对应新增能力 local-data-persistence，并记录于 ADR `docs/adr/0001-windows-desktop-local-sqlite.md`。
- 工作台信息架构与数据录入方式已通过高保真录入原型选择确认（客户决定以 A「任务指挥台」为主，保留 B 的「生命周期吞吐」板块和 C 的「当前上下文」板块；选定原型 `prototype/relocation-workbench/selected/relocation-workbench-selected.html` 已升级为高保真录入原型，是设计依据，不是生产代码，后续将更新）：待办快速处理改为**项目提醒快速处理**，与高密度项目队列共同构成主操作流；生命周期吞吐是紧凑全局节奏视图（六阶段项目数、平均停留、流入流出与瓶颈提示，可点击筛选项目队列）；当前上下文是随选中项目/待办/阶段联动的常驻侧栏（状态与异常、当前提醒、金额闭环、Ship-to/二维码/损坏维修等非阻塞事项）；项目总览、搬迁仪器、搬迁批次、上门活动、费用与掉票、申请与维修六个详情 tab 按需展开。数据录入为已确认界面要求：新建搬迁项目采用四步向导（基本信息、搬迁范围、执行准备、确认方式），提供保存为待进单、正式进单、未进单先执行三个确认路径，向导录入单号时参与工程师必填（未选定工程师拒绝保存整个向导并就地提示），填写且已选定工程师时项目与自动创建的对应开单记录同次保存（开单时间默认当前时间、备注可空）；上门活动在同一页面记录拆机事实（拆机状态及拆机开始/完成时间）与各工作类型状态/时间；项目主状态可人工选择但调用生命周期校验并就地反馈（含合同金额为 0 时的维修限制等）；未进单与已进单项目颜色明显不同；当前项目通过快速记录就近录入搬迁批次、搬迁仪器、上门活动、开单记录、实际物流费用、验收报告、掉票、Ship-to 申请、损坏/维修事项、补齐进单核心资料等业务动作（二维码申请与序列号地址更新为独立模块，不进快速记录），项目队列、当前上下文与详情 tab 均提供就近入口；点击项目提醒直达对应项目；报表支持 Excel（.xlsx）、PNG、PDF 导出并就地反馈；视觉采用高可读企业运营风格，具备合理字号、间距、层级与表单反馈（Modal/Drawer/Toast、必填/可后补标识、校验反馈、键盘焦点与 Escape 关闭）。以上均为客户确认的界面决策，不属于 TBD 暂定范围。

### 客户最终答复（TBD-01~25）

TBD-01~25 已全部由客户确认（2026-08-07），逐项结论如下（均已并入 docs v0.3 与各能力规格，不再属于未决暂定项）：

1. **TBD-01** 待进单阶段合同可空（可不关联合同）；正式进单前必须补齐合同；不再强制待进单时创建空合同草稿；项目稳定内部 ID 与临时编号保留，正式进单补唯一 ECC。
2. **TBD-02** 搬迁仪器必须登记仪器名称；非空序列号在同一合同/其唯一搬迁项目内不得重复、跨合同可重复；允许无序列号占位，暂定数量不生成虚拟仪器。
3. **TBD-03** 运输前允许无批次或改批，但每次改批保存改批历史（原批次、新批次、变更时间、登录账号归属）；运输后禁止直接改批。
4. **TBD-04** Ship-to 申请不自动关联仪器/项目，只记录客户名称与新址地址；状态线性流转：待提交 → 处理中 → 已完成，不支持退回或取消；Account ID 完成前必填，补入后创建/对应不可变 Ship-to；实际仪器地址仍由序列号地址更新事实表达。
5. **TBD-05** 保留活动 × 仪器 × 工作类型（拆机/装机/维修/其他）全部模型；在同一上门活动页面记录；拆机事实明确记录拆机状态及拆机开始/完成时间，其他工作类型记录各自状态/时间。
6. **TBD-06** 二维码申请不设状态流转；工作量按一条申请中去重后的申请类型数量计数；多条申请分别计数；不关联项目/仪器。
7. **TBD-07** 实际装机完成时间仍自动触发进入待验收；项目验收后仍允许报修/维修且不影响验收、待掉票或完成状态。
8. **TBD-08** 未进单项目与已进单项目在界面使用明确不同颜色/视觉标识；不再保留"进单后按事实自动跳待执行/执行中/待验收"的旧暂定规则；实际装机完成、项目验收和金额闭环等已明确自动触发仍生效。
9. **TBD-09** 负责人可直接选择/人工调整项目主状态；系统校验合法状态、取消约束、TBD-07 实际装机自动待验收、验收报告自动待掉票、金额闭环自动已完成/回待掉票；移除"主状态完全由事实推导且不可编辑"旧规则。
10. **TBD-10** 取消不可恢复；继续工作需重新新增项目；有任何掉票历史（含撤销）不能取消；取消后金额/掉票不可改；取消项目排除进单金额/收入/掉票/闭环指标，真实成本保留并标取消。
11. **TBD-11** 金额最多两位小数、十进制定点、不得负数；仅"合同 USD 含税金额"允许 0；其他录入金额必须 > 0；最终可确认不得低于累计掉票；合同金额修改按 TBD-20 直接覆盖；非待掉票/已完成状态金额修改不影响主状态；合同金额为 0 时正式进单的最终可确认金额不能默认成 0，必须另行录入 > 0 值。
12. **TBD-12** 区域手工记录，trim 后精确分组，实时重算。
13. **TBD-13** 工作量按相应申请/动作时间归月；归属当前登录本地账号快照；损坏/维修事项内的单个备件新增"备件申请时间"与备件处理状态（待提交、处理中、已到件、已使用）；仅"已使用"备件计入维修费用与合同占比；不重新引入独立备件申请对象/入口。
14. **TBD-14** 物流费用新增/明确"物流费用申请（登记）时间"，以该时间所属月份归属；物流仍人民币登记；实际物流费用按固定汇率折算 USD 后除以最新合同 USD 含税金额展示"物流费用合同占比"；合同金额空/0 时占比不可计算并提示；成交 > 预算允许保存仅警告，不阻塞、不自动创建项目提醒。
15. **TBD-15** 合同金额为空或 0 时，可登记损坏，但禁止开始/完成维修，禁止把备件标为"已使用"；补齐正数合同金额后才允许；同步损坏/维修状态校验和维修活动关联。
16. **TBD-16** 保持单一本地应用账号修订（不是无登录）。
17. **TBD-17** 报表手工选择月份区间、实时更新；支持导出 Excel（.xlsx）、图片（PNG）与 PDF，导出当前筛选实时结果；删除仅 CSV/默认当前季度的旧规则；区域/业务类型/运输公司/工程师等筛选可保留，月份必须手工选择、不设默认季度。
18. **TBD-18** 历史迁移以 ECC 为项目/合同聚合主键，同一 ECC 下一个合同的全部执行数据均聚合导入并展示；服务单号/Account ID/序列号用于子记录识别与冲突，不与 ECC 同级匹配项目；缺 ECC 的项目/合同执行数据在校验中报必填错误；原已确认的只读校验、整体事务、幂等、冲突、forward-fix、源时间规则继续有效，执行方式由工作台外脚本改为登录后的工作台内向导（见《已确认范围》存量数据迁移段）。
19. **TBD-19** 掉票不能物理删除；撤销后为终态，禁止编辑、重复撤销或重新激活；更正需新增有效掉票。
20. **TBD-20** 合同金额可直接覆盖当前值，不保存正式合同变更对象/历史、不要求原因；进单金额快照保持原值；最终可确认金额保持原值、不随合同覆盖同步；仍校验其他金额规则。
21. **TBD-21** 非空服务单号全局唯一；迁移发现不同源记录重复非空服务单号进入冲突清单，解决前禁止提交。
22. **TBD-22** 认证/单寄备件/PM 开单字段：开单时间、服务单号、开单类型、工程师、客户单位；备注可选；开单时间未填默认当前时间；搬迁开单关联项目规则不变。
23. **TBD-23** 删除七类自动标准待办与所有派生/自动完成/关键日期规则；改为"项目提醒"：每个搬迁项目由负责人手工维护一个当前提醒时间与备注内容，可编辑或清除，不保存提醒完成历史；系统不根据缺失字段自动生成提醒；到期分类按提醒时间显示临期/今日/逾期，临期窗口可配置默认 7 天；提醒仅工作台内；自定义待办概念并入项目提醒；主工作流改为"项目提醒快速处理 + 项目队列"。

25. **TBD-25** 客户名称为客户唯一业务标识（trim 后唯一），ECC 为搬迁项目/合同全局唯一标识；可保留内部 ID 作技术引用，但删除客户外部编号与"客户名称可重复"旧规则；一个客户名称可关联多个不同 ECC 项目。
