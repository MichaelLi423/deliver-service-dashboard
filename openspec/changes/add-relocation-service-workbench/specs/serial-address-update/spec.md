# serial-address-update

## Purpose

本能力定义搬迁仪器序列号地址更新事实的行为规则：当搬迁仪器实际迁往一处新址地址时，负责人逐台登记一条序列号地址更新事实，记录客户名称、新址地址、序列号、Account ID 与更新时间。项目级新址地址仅作为默认计划，单条更新事实表达该台仪器的实际关联新址。更新事实不得创建、修改或删除 Account ID 对应的不可变 Ship-to。更新时间必填、默认当前时间并可补录历史时间；系统提供更新事实列表与筛选，并按更新时间所属月份计数。客户名称、新址地址、序列号、Account ID 与更新时间为非空必填字段，序列号校验仅要求非空且与登记仪器一致，不引入未确认的序列号格式约束。

## ADDED Requirements

### Requirement: 序列号地址更新事实逐台登记

搬迁仪器实际迁往新址地址时，系统 SHALL 为每台搬迁仪器创建一条逐台关联的序列号地址更新事实；每条更新事实 SHALL 记录客户名称、新址地址、序列号、Account ID 与更新时间。一台搬迁仪器 SHALL 可拥有多条更新事实以表达多次地址变化。

#### Scenario: 逐台创建更新事实

- **GIVEN** 一台搬迁仪器实际迁往一处新址地址
- **WHEN** 负责人为该仪器登记序列号地址更新
- **THEN** 系统创建一条与该台仪器逐台关联的更新事实
- **AND** 该事实记录客户名称、新址地址、序列号、Account ID 与更新时间

#### Scenario: 一台仪器多次地址变化

- **GIVEN** 一台搬迁仪器先后发生多次地址变化
- **WHEN** 负责人逐次登记序列号地址更新
- **THEN** 每次登记各创建一条与该仪器关联的更新事实
- **AND** 各条更新事实按更新时间保留并可追溯

### Requirement: 项目新址为默认计划、更新事实表达实际关联

项目级新址地址 SHALL 仅作为默认计划，MUST NOT 自动成为每台搬迁仪器的实际关联新址；每台搬迁仪器的实际关联新址 SHALL 以该仪器对应的序列号地址更新事实表达。未登记更新事实的仪器 SHALL NOT 视为已关联新址。

#### Scenario: 项目新址仅作默认计划

- **GIVEN** 某搬迁项目已记录项目级新址地址
- **WHEN** 系统确定某台搬迁仪器的实际关联新址
- **THEN** 项目级新址仅作为默认计划提示
- **AND** 不自动成为该台仪器的实际关联新址

#### Scenario: 更新事实表达实际关联

- **GIVEN** 某台搬迁仪器存在一条记录新址地址的更新事实
- **WHEN** 系统展示该仪器的实际关联新址
- **THEN** 系统以该仪器最近一条更新事实的新址地址为准
- **AND** 与项目级默认计划不一致时以更新事实为准

#### Scenario: 未登记更新事实不视为已关联

- **GIVEN** 某台搬迁仪器尚未登记任何序列号地址更新事实
- **WHEN** 系统确定该仪器的实际关联新址
- **THEN** 系统不认定该仪器已关联新址
- **AND** 项目级新址不替代该仪器的实际关联状态

### Requirement: 不修改不可变 Ship-to

序列号地址更新事实 MUST NOT 创建、修改或删除 Account ID 对应的 Ship-to；Account ID 对应的 Ship-to SHALL 保持不可变。更新事实 SHALL 仅记录仪器与新址的关联信息，不改变任何 Ship-to 主数据。

#### Scenario: 更新事实不修改 Ship-to

- **GIVEN** 一条序列号地址更新事实已记录 Account ID 与新址地址
- **WHEN** 系统保存该更新事实
- **THEN** 该 Account ID 对应的 Ship-to 数据保持不变
- **AND** 更新事实不创建、不修改也不删除任何 Ship-to 主数据

### Requirement: 更新时间必填、默认当前、可补录

更新时间 SHALL 为必填字段；创建更新事实时系统 SHALL 默认填入当前时间；负责人 SHALL 可将更新时间补录或改为历史时间，以反映实际发生时间。

#### Scenario: 创建时默认当前时间

- **GIVEN** 负责人登记一条序列号地址更新事实且未填写更新时间
- **WHEN** 保存该更新事实
- **THEN** 系统以当前时间作为更新时间
- **AND** 更新时间作为必填字段被保存

#### Scenario: 补录历史时间

- **GIVEN** 负责人补录一条历史序列号地址更新事实
- **WHEN** 填写历史更新时间并保存
- **THEN** 系统以所填历史时间作为更新时间
- **AND** 后续按更新时间计数时归属该历史时间所属月份

### Requirement: 更新事实列表、筛选与按更新时间计数

系统 SHALL 提供序列号地址更新事实列表，并 SHALL 支持按客户、新址地址、序列号、Account ID 或更新时间筛选；按更新时间计数时 SHALL 以每条更新事实的更新时间所属月份归属。

#### Scenario: 列表展示与筛选

- **GIVEN** 系统中存在多条序列号地址更新事实
- **WHEN** 负责人查看更新事实列表
- **THEN** 系统展示客户名称、新址地址、序列号、Account ID 与更新时间
- **AND** 支持按客户、新址地址、序列号、Account ID 或更新时间筛选

#### Scenario: 按更新时间所属月份计数

- **GIVEN** 多条更新事实的更新时间分布在不同月份
- **WHEN** 系统按更新时间统计更新事实数量
- **THEN** 每条更新事实按更新时间所属月份归属
- **AND** 同月更新事实合计为该月更新计数

### Requirement: 非空字段与序列号校验

客户名称、新址地址、序列号、Account ID 与更新时间 SHALL 为非空必填字段，任一缺失 SHALL 拒绝保存；序列号 SHALL 非空且与登记的搬迁仪器一致，不一致时 SHALL 拒绝保存。系统 MUST NOT 引入未确认的序列号格式约束。

#### Scenario: 非空字段缺失拒绝保存

- **GIVEN** 一条序列号地址更新事实缺少客户名称、新址地址、序列号、Account ID 或更新时间
- **WHEN** 负责人提交保存
- **THEN** 系统拒绝保存并提示缺失字段
- **AND** 不产生部分保存的更新事实

#### Scenario: 序列号与登记仪器一致

- **GIVEN** 负责人登记一台搬迁仪器的地址更新但填写的序列号与该仪器不一致
- **WHEN** 负责人提交保存
- **THEN** 系统拒绝保存并提示序列号与登记仪器不一致
- **AND** 序列号一致后才允许保存

#### Scenario: 不引入未确认序列号格式

- **GIVEN** 序列号符合非空且与登记仪器一致的要求
- **WHEN** 系统校验该序列号
- **THEN** 系统不施加任何未确认的序列号格式或长度约束
- **AND** 仅校验非空与仪器一致性即可保存
