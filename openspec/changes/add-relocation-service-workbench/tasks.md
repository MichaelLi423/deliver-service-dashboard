# 搬迁服务工作台 · 实施任务

本文件按依赖顺序拆分实施任务，属规划工件，不包含代码实现。实施基准为 docs/搬迁服务工作台.md v0.3（客户已确认）、proposal.md（已确认范围与客户最终答复，TBD-01~25 全部已解决、剩余未决=0、高风险=0）、design.md（D1~D29 逻辑设计）与 15 份能力规格（specs/*/spec.md）。工作台信息架构与数据录入以客户确认的高保真录入原型（prototype/relocation-workbench/selected/relocation-workbench-selected.html）为设计依据，其行为、结构与视觉意图由 workbench-interface 规格定义（见第 9 组）；原型不是生产实现，视觉与可用性基线（字号、层级、表单反馈、1024/1440 适配）按 workbench-interface 规格执行，具体组件实现细节由 apply 阶段决定，本文件不预设。访问边界已确认（单一本地应用账号：首次启动初始化、后续登录、一次性恢复码重置；无多账号、注册、角色与权限管理，无远程认证、外部身份源与账号同步；账号仅为访问门槛、不加密 SQLite，Windows 操作系统账户仍是本机数据文件与备份的主要保护边界，见 ADR docs/adr/0001-windows-desktop-local-sqlite.md 与 design D12）；运行与持久化架构已确认（Windows 桌面、Electron + React + TypeScript、本地 SQLite、自动/手动备份恢复，见 ADR 与 design D17/D18）。

约定：模块所有权为 relocation-project-lifecycle 唯一拥有主状态转换/校验入口（design D4），workbench-todos（项目提醒）与 operational-reporting 只消费事实、不拥有业务状态（D9/D10），operational-reporting 唯一拥有统计公式，workbench-interface 为表现层、只消费事实与校验结果、只定义录入入口与反馈、不重复业务状态与金额校验规则（D14~D16），local-data-persistence 拥有本地数据存储、备份与恢复（D17/D18），workbench-access 拥有本地账号访问与事实归属（D12）。验证顺序为领域层场景测试优先、UI 层冒烟验收在后（见 10.4），每个任务以"完成态"给出可验证验收标准。技术栈与关键实现细节已在 0.2 决策确定（Electron 43.3.0、Forge 7.11.2 + webpack-typescript + React、node:sqlite、PRAGMA user_version 迁移、userData/data、在线 backup + integrity_check + 原子恢复、安全快照、WAL/foreign_keys/busy timeout、金额分整数、业务日期 yyyy-mm-dd 与审计/技术时间精确 ISO（时间口径见 design D30）；Excel/PNG/PDF 导出技术库可留 apply 时选择但格式已定；Vitest/RTL/Playwright Electron Windows）。TBD-01~25 已全部确认、剩余未决=0、高风险=0，不再存在"按模块复核"要求；本文件最终任务（10.7/10.8）要求运行 openspec validate 与等效验证流程，但仅在 apply 阶段执行。
