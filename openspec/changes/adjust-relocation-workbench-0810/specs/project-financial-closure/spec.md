# 项目财务闭环

## ADDED Requirements

### Requirement: 待掉票金额指标仅由仍存在项目的有效财务事实计算

待掉票金额指标（含尚待掉票等金额闭环展示）SHALL 仅由仍存在项目（引用有效且存在）的有效财务事实计算；掉票、最终可确认金额等财务事实引用已不存在的项目（孤立关联或脏数据）时，SHALL NOT 计入指标；系统中不存在任何项目时，待掉票金额指标 SHALL 为 0，SHALL NOT 因孤立或脏数据显示非 0；系统 SHALL 提供对孤立/脏财务事实的诊断、清理与防复发路径。本治理 SHALL NOT 将指标口径改为"仅活跃项目"，也 SHALL NOT 改变掉票记录仅可撤销、不可物理删除且撤销为终态的既有规则（见"掉票撤销终态而非删除"）；指标的报表消费口径由 operational-reporting 能力定义，本能力不重复统计公式。

#### Scenario: 无任何项目时待掉票金额为 0

- **GIVEN** 数据库中仅存在孤立或脏财务事实，不存在任何搬迁项目
- **WHEN** 系统计算待掉票金额指标
- **THEN** 指标为 0
- **AND** 不因孤立或脏数据展示非 0 的待掉票金额

#### Scenario: 孤立财务事实不污染指标

- **GIVEN** 一条掉票或最终可确认金额事实引用的项目已不存在
- **WHEN** 系统计算待掉票金额指标
- **THEN** 该事实不计入指标
- **AND** 该事实被诊断为孤立关联

#### Scenario: 仍存在项目的有效财务事实计入指标

- **GIVEN** 掉票与最终可确认金额事实关联的项目仍存在
- **WHEN** 系统计算待掉票金额指标
- **THEN** 指标按这些有效财务事实计算

#### Scenario: 诊断清理与防复发

- **GIVEN** 系统检测到孤立/脏财务事实
- **WHEN** 负责人执行清理
- **THEN** 系统提供诊断结果与清理路径
- **AND** 清理后待掉票金额指标不再受孤立数据影响，并具备防复发校验

#### Scenario: 治理不改变掉票撤销终态与不可物理删除

- **GIVEN** 一条掉票记录（含被判定为孤立关联的掉票记录）
- **WHEN** 系统执行孤立数据治理
- **THEN** 系统不提供物理删除掉票记录
- **AND** 掉票记录仍仅可通过撤销处理并保持终态，更正需新增有效掉票
