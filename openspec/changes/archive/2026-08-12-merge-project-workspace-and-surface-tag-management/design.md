## Context

现有 renderer 工作台将当前上下文与项目详情放在 `workbench-grid` 双列中，详情区域存在 760px/680px 固定最大高度与内部裁切。项目提醒、项目详情和项目队列未形成单列的连续处理顺序，标签库维护入口也只在“数据管理”二级菜单中。动机与行为要求见 `proposal.md` 及本 change 的 `specs/workbench-interface/spec.md`。

约束：renderer 无 Node 环境，现有全局标签库维护能力、项目选择和详情联动均已存在；本次不改后端、数据库或 `src/shared/ipc.ts` IPC 契约。

## Goals / Non-Goals

**Goals:**

- 在现有工作台状态模型内形成真实 DOM 顺序为 reminders → project-workspace → queue 的单列主工作区。
- 将 `ProjectContext` 作为项目工作区顶部摘要、`ProjectDetails` 作为下部详情 tabs，二者复用已有选中项目状态和事件联动。
- 直接暴露既有标签库维护入口，并修正工作台范围内的滚动边界与窄桌面可用性。

**Non-Goals:**

- 不重写标签库、项目详情 tabs、提醒处理或项目队列业务能力。
- 不新增后端接口、IPC、持久化字段、依赖或第二套项目选择状态。
- 不改变项目提醒、金额闭环、生命周期或标签分类的领域规则。

## Decisions

### 1. 以单一项目工作区替代双列区域

工作台在提醒日期泳道后渲染一个全宽 `project-workspace` 容器：先渲染 `ProjectContext` 摘要，再渲染 `ProjectDetails` tabs，最后渲染高密度项目队列。保留各组件既有 props、回调和由工作台父级持有的 selected project state。

这样可保证点击提醒、队列或生命周期阶段时，同一次状态更新同时驱动摘要与 tabs；不创建第二个上下文、详情实例或派生选中状态。备选的“双列调换位置”继续制造分散阅读与窄宽布局问题；复制摘要或详情以适配不同区域会导致状态漂移，因此不采用。

### 2. 复用标签库入口，仅提升导航可发现性

顶部主导航新增直接“标签管理”动作，调用当前“数据管理”中用于打开全局标签库维护的同一处理逻辑。现有数据管理中的入口可按实现需要保留或移除，但直接导航入口必须可见且不能创建第二个维护页面或状态源。

复用现有入口确保标签分组、标签数据和维护行为保持一致；新建独立模块会重复 UI 与状态，因此不采用。

### 3. 以区域级滚动替代页面级横向滚动和详情裁切

移除 `workbench-grid` 的双列约束及详情的 760px/680px `max-height`/裁切规则，使项目工作区随页面自然增长。页面外层约束横向尺寸并允许子项收缩；只有队列表格或项目工作区内不可压缩内容在自身滚动容器中横向滚动。

通过 1440px、1190px、1170px、1024px 断点或等效的弹性约束验证内容不推动页面横向溢出。保留固定详情高度会继续截断 tabs 内容；让整个页面横向滚动会破坏核心操作连续性，均不采用。

### 4. 先以可观察行为建立回归覆盖

先补 renderer/E2E 红灯测试，覆盖顶栏直接标签管理、单列 DOM 顺序、项目工作区的单实例联动、移除详情裁切和各目标宽度的页面级横向溢出。再调整入口、DOM 与 CSS；测试断言用户可观察结果，而非私有实现细节。

## Risks / Trade-offs

- [将详情固定高度移除后页面变长] → 让页面纵向滚动，保持详情 tab 按需渲染，并以 E2E 验证关键操作仍可达。
- [弹性宽度调整可能使队列表格列压缩] → 对不可压缩表格保留区域内横向滚动，禁止页面级横向滚动。
- [复用组件时误引入局部选中状态] → 仅由现有工作台父级选择状态传递 props 与回调，增加联动测试。
- [导航入口迁移破坏既有维护入口] → 两个入口在迁移期间调用同一打开动作，并以 renderer/E2E 测试验证全局标签库可达。

## Migration Plan

1. 增加失败的 renderer 与 E2E 回归测试。
2. 调整 renderer 工作台入口、DOM 顺序与样式，复用既有组件和标签管理打开动作。
3. 运行 focused renderer 测试、类型检查、打包和单 worker Playwright；确认 1024px、1170px、1190px、1440px 行为。
4. 此变更无数据或 IPC 迁移；若需回滚，恢复 renderer DOM/CSS 和导航入口即可，已有数据不受影响。
